# Task 1 result

## Changed

- `src/clock.ts`: added the `Clock` port (`now`, `sleep`), `systemClock` backed by `Date`/`setTimeout`, and `FakeClock` with a frozen `current` value, sleeper queue ordered by due time, and `advance` that resolves due sleepers one at a time and awaits `setImmediate` after each so chained work runs before `advance` settles.
- `src/runtime/errors.ts`: added `RuntimeError` (keeps `message`/`cause`, sets `name` from `new.target.name`) and the four subclasses `ImageNotFoundError`, `ContainerNotFoundError`, `NameConflictError`, `RuntimeUnavailableError`.
- `src/runtime/types.ts`: added `MANAGED_LABEL`, `RestartPolicy`, `PublishedPort`, `VolumeMount`, `ContainerSpec`, `ContainerState`, `ContainerSummary`, `ContainerInfo`, `EngineInfo`, `LogEntry`, `LogOptions`, and the `ContainerRuntime` interface. Imports nothing.
- `tests/clock.test.ts`: tests for real-time `systemClock`, fake-clock freeze/mutation, single and multiple sleepers, due ordering, `sleep(0)`, and work chained on resolved sleeps.
- `tests/runtime-errors.test.ts`: tests that each subclass is a `RuntimeError`/`Error`, keeps its class name, message, and `cause`; also asserts `MANAGED_LABEL`.

## Deviated

- The task's port listing showed the four error subclasses with empty bodies. A literal empty body would inherit `name === "RuntimeError"`, which fails the acceptance line requiring `name` equal to the class name. I kept the empty subclass declarations but set `this.name = new.target.name` in the `RuntimeError` constructor so each subclass reports its own class name. Public signatures are unchanged.
