## Context

Reuse the ports from task 1: `ContainerRuntime` and its types plus `MANAGED_LABEL` from `src/runtime/types.ts`, the errors from `src/runtime/errors.ts`, and `Clock`, `systemClock`, `FakeClock` from `src/clock.ts`. Do not edit those files. No dependency changes; there is no network.

`tests/support/runtime-contract.ts` does not end in `.test.ts`, so the test glob does not run it directly; `tests/runtime-fake.test.ts` calls it. The suite must use only `ContainerRuntime` methods and the harness images, never `FakeRuntime` internals, because the `docker-podman-adapter` change will run it against real engines. For the same reason, contract tests must not assume log content from `images.present`, and they give each container a name unique within the test.

The fake schedules a delayed exit with `clock.sleep(exitAfterMs).then(...)` at start, and applies it only if that same start of the container is still running. `FakeClock.advance` runs such continuations before it settles. The fake uses no `setTimeout` of its own. Unscripted containers run until stopped; stop records exit code 0. The restart policy is stored and never acted on.

## Ports

```ts
// src/runtime/fake.ts
export interface FakeImageScript {
  exitCode?: number;   // the container exits with this code; without exitAfterMs, as soon as it starts
  exitAfterMs?: number; // delay on the injected clock before exiting with exitCode
  logs?: { stream: "stdout" | "stderr"; text: string }[]; // written at each start, timestamped clock.now()
}
export interface FakeRuntimeOptions {
  clock?: Clock;                            // default systemClock
  pullFailures?: string[];                  // refs whose pullImage rejects with ImageNotFoundError
  scripts?: Record<string, FakeImageScript>; // keyed by image ref
}
export class FakeRuntime implements ContainerRuntime {
  constructor(options?: FakeRuntimeOptions);
  unavailable: boolean; // when true, every method rejects with RuntimeUnavailableError
}
// ping() resolves { name: "fake", version: "0.0.0" }; ids are "fake-1", "fake-2", ... in creation order.

// tests/support/runtime-contract.ts
export interface ContractHarness {
  runtime: ContainerRuntime;
  images: { present: string; missing: string }; // present pulls and runs until stopped; missing fails to pull
  teardown?(): Promise<void>;
}
export function runtimeContract(label: string, factory: () => Promise<ContractHarness>): void;
```

## Acceptance
- [ ] `runtimeContract` registers one `describe` named `container runtime contract: <label>`; each test gets a fresh harness from `factory` and calls `teardown` in a `finally`.
- [ ] Contract, engine and images: `ping` returns a non-empty name and version; `pullImage(images.present)` resolves and `pullImage(images.missing)` rejects with `ImageNotFoundError`; `createContainer` from an image never pulled rejects with `ImageNotFoundError`; `ensureNetwork` and `ensureVolume` each resolve when called twice with the same name.
- [ ] Contract, create and inspect: `createContainer` returns an id; inspecting by id and by name gives the same container with state `created`, `exitCode`, `startedAt`, and `finishedAt` `null`, `restartCount` 0, and labels equal to the spec's labels plus `paas.managed=true`; creating another container with the same name rejects with `NameConflictError`, also after the first has exited.
- [ ] Contract, lifecycle: start gives `running` with `startedAt` set; starting again changes nothing; `stopContainer(x, { timeoutSeconds: 1 })` gives `exited` with a numeric `exitCode` and `finishedAt` set; stopping again resolves; `removeContainer` on a running container without `force` rejects with a `RuntimeError` and leaves it running, with `force` removes it; start, stop, remove, inspect and logs on an unknown name reject with `ContainerNotFoundError`.
- [ ] Contract, list and logs: with containers A `{x:"1",y:"1"}`, B `{x:"1"}`, C `{x:"1",y:"1"}` (C exited), `listContainers({x:"1",y:"1"})` returns exactly A and C; `containerLogs` returns entries oldest first, `tail: 1` returns at most one entry, and `since` one hour after now returns none.
- [ ] `tests/runtime-fake.test.ts` calls `runtimeContract("fake", ...)` with a new `FakeRuntime` whose `pullFailures` holds the harness's missing image, and asserts `ping` returns `fake`/`0.0.0` and ids are `fake-1`, `fake-2` in creation order.
- [ ] Fake scripting, with a `FakeClock`: a script with `exitCode` 3 and no delay makes inspection right after `startContainer` show `exited`, code 3; a script with `exitCode` 1 and `exitAfterMs` 2000 is `running` after `advance(1999)` and `exited`, code 1, `finishedAt` equal to `clock.now()` after `advance(1)`; scripted logs at three clock times honor `since` plus `tail` (only the newest returned for `since` = the second time and `tail: 1`); with `unavailable = true`, `ping` and `listContainers` reject with `RuntimeUnavailableError`.
