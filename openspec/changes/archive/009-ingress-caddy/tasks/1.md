## Context

Contract: "Ingress settings" in the `app-state` delta.

Append migration 2 to `MIGRATIONS` in `src/state/db.ts`: `CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL)`. Do not edit migration 1. `tests/state-db.test.ts` already reads `MIGRATIONS.length`, so it keeps passing unchanged.

All SQL stays in `src/state/settings.ts`. Keys are `ingress.tls`, `ingress.http_port` and `ingress.https_port`; ports are stored as decimal text. Check the merged result (stored values plus the new ones) before writing, so equal HTTP and HTTPS ports are refused even when only one is given. Write all given values in one transaction. Throw `ValidationError` from `src/state/errors.ts`. Reuse the rules of `validatePort` in `src/state/validate.ts`, but with the fields `httpPort` and `httpsPort` and the messages `invalid http port <n>` and `invalid https port <n>`. An unknown mode fails with field `tls` and message `invalid TLS mode "<mode>": use off or auto`. Equal ports fail with field `httpsPort` and message `https port <n> is also the http port`.

Tests use `openStore(":memory:")`, and a temporary file database for the reopen case.

## Acceptance
- [ ] A new in-memory store returns `{ tls: "off", httpPort: 80, httpsPort: 443 }`, and `schemaVersion` equals `MIGRATIONS.length`, which is 2.
- [ ] Setting only `httpPort: 8080` returns and stores `{ tls: "off", httpPort: 8080, httpsPort: 443 }`, and a reopened file database returns the same.
- [ ] Setting `tls: "auto"` keeps previously stored ports.
- [ ] `tls: "on"` fails with `ValidationError` field `tls`; `httpPort: 0` and `httpsPort: 70000` fail with fields `httpPort` and `httpsPort`; nothing is stored in any of these cases.
- [ ] With HTTP port 8080 stored, setting `httpsPort: 8080` fails with `ValidationError` field `httpsPort`, and HTTPS stays 443; `{ httpPort: 443, httpsPort: 80 }` in one call succeeds.
- [ ] `tests/state-db.test.ts` passes unchanged.
