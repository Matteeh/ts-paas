## Context

Contract: "Caddy container", "Admin API on loopback only", "Idempotent up", "Ingress down", "Pushing config", "Waiting for the admin API" and "Ingress status" in the `ingress` delta.

Reuse `buildCaddyConfig`, `desiredRoutes` and `routesFromConfig` from `src/ingress/config.ts`; `CaddyAdmin` and `AdminUnreachableError` from `src/ingress/admin.ts`; `getIngressSettings` and `setIngressSettings` from `src/state/settings.ts`; and `PAAS_NETWORK` and `DEFAULT_STOP_TIMEOUT_SECONDS` from `src/deployments/types.ts`. Talk to the engine only through `ContainerRuntime`, and treat `ContainerNotFoundError` as "missing". Do not edit files outside `scope`.

The container spec has name `target.container`, image `CADDY_IMAGE`, network `paas-net`, restart policy `unless-stopped`, env `{ CADDY_ADMIN: "0.0.0.0:2019" }`, and labels `paas.ingress=caddy`, `paas.ingress.http-port=<n>` and `paas.ingress.https-port=<n>`. It publishes `{ hostIp: "", hostPort: httpPort, containerPort: 80 }`, `{ hostIp: "", hostPort: httpsPort, containerPort: 443 }` and `{ hostIp: "127.0.0.1", hostPort: target.adminPort, containerPort: 2019 }`; an empty `hostIp` is every host address. It mounts `target.volume` at `/data`.

`ingressUp` calls `setIngressSettings` first, so an invalid value throws `ValidationError` before any runtime call. Creating means `pullImage`, `ensureNetwork`, `ensureVolume`, `createContainer` and `startContainer`. It then pushes `buildCaddyConfig(settings.tls, desiredRoutes(store))`, retrying only on `AdminUnreachableError`, with `clock.sleep(250)` between attempts and at most 40 sleeps. `syncIngress` pushes once without retrying, and only when the container is `running`.

`target` defaults to `DEFAULT_TARGET`. The integration test in task 7 passes its own.

Tests use `FakeRuntime` with a `FakeClock`, `FakeCaddyAdmin`, and `openStore(":memory:")`. To see container specs and pull calls, subclass `FakeRuntime` in the test file and record `createContainer` and `pullImage` before calling `super`. The retry test starts `ingressUp`, then awaits `clock.advance(250)` twice before awaiting the promise.

```ts
// src/ingress/caddy.ts
export const CADDY_IMAGE = "docker.io/library/caddy:2";
export interface IngressTarget { container: string; volume: string; adminPort: number; }
export const DEFAULT_TARGET: IngressTarget; // { container: "paas-caddy", volume: "paas-caddy-data", adminPort: 2019 }
export interface IngressDeps { store: Store; runtime: ContainerRuntime; clock: Clock; admin: CaddyAdmin; target?: IngressTarget; }
export type UpAction = "created" | "recreated" | "started" | "unchanged";
export interface UpResult { action: UpAction; settings: IngressSettings; routes: IngressRoute[]; }
export interface IngressStatus { caddy: "running" | "stopped" | "missing"; settings: IngressSettings; routes: IngressRoute[] | null; }
export function ingressUp(deps: IngressDeps, changes?: Partial<IngressSettings>): Promise<UpResult>;
export function ingressDown(deps: IngressDeps): Promise<boolean>; // true when a container was removed
export function ingressStatus(deps: IngressDeps): Promise<IngressStatus>;
export function syncIngress(deps: IngressDeps): Promise<boolean>; // true when a config was pushed
```

## Acceptance
- [ ] A first `ingressUp` reports `created`; the recorded spec matches Context exactly; `paas-net` exists; the container is running; the admin received one config equal to `buildCaddyConfig("off", desiredRoutes(store))`.
- [ ] Container port 2019 is published only with `hostIp` `127.0.0.1`, and the ports 80 and 443 bindings use `hostIp` `""`; with a target whose `adminPort` is 12019 the admin binding uses host port 12019.
- [ ] A second `ingressUp` with the same settings reports `unchanged`, pulls nothing, and keeps the container id; after `runtime.stopContainer("paas-caddy")` it reports `started` with the same id; `ingressUp(deps, { httpPort: 8080 })` then reports `recreated` with a new id and host port 8080.
- [ ] `ingressUp(deps, { tls: "on" as TlsMode })` rejects with `ValidationError` and makes no runtime call; an admin that fails twice with `AdminUnreachableError` and then succeeds resolves after two 250 ms advances; one `AdminRequestError` rejects at once.
- [ ] `ingressDown` stops and removes the container and resolves `true`, and a second call resolves `false`; it never calls `ensureVolume` or removes anything else.
- [ ] `syncIngress` resolves `false` without calling the admin when the container is missing or stopped; when it runs, it pushes once, resolves `true`, and rejects with the admin's error when the push fails.
- [ ] `ingressStatus` reports `missing` with `routes: null` before up, `stopped` with `routes: null` for a stopped container, and `running` with `routesFromConfig(await admin.getConfig())` while up; `settings` is always the stored settings.
