## Context

Contract: "Ingress follows deploys and stops", "Deploy command", "Deploy JSON" and "Stop command" in the `cli` delta, and "Running hook" in the `deployments` delta.

In `registerDeploy` in `src/commands/deploy.ts`, pass `onRunning` to `deploy`. It calls `syncIngress` from `src/ingress/caddy.ts` with the engine deps plus `admin: getAdmin(context)` from `src/commands/context.ts`. When `deploy` rejects with an error from that hook, print the running record first if `--json` is set, then throw `deployment <id> is running, but ingress update failed: <message>`. Let `AppNotFoundError` and `DeploymentInProgressError` pass through as today. In `registerStop` in `src/commands/stop.ts`, call `syncIngress` after `stopApp` returns and the `stopped` line is printed. If it rejects, throw `<app> is stopped, but ingress update failed: <message>`.

`syncIngress` does nothing when `paas-caddy` is missing, so the frozen `tests/deploy-cli.test.ts` and `tests/status-logs-cli.test.ts` pass unchanged.

Tests build the program in-process as `tests/deploy-cli.test.ts` does, with one `FakeRuntime`, a `FakeClock` advanced past the health window, and a `FakeCaddyAdmin` passed as `admin`. Copy the helpers; do not import from it. Bring ingress up with `paas ingress up` first. To check the no-removed-container rule, set `FakeCaddyAdmin.onLoad` to inspect, for every upstream in `routesFromConfig(config)`, the container named before the `:`, and record any that is not `running`. Make a push fail by pushing an `AdminRequestError` onto `failures` just before the call.

## Acceptance
- [ ] With ingress up, deploying `web` (hostname `web.localhost`, port 8080) exits 0, and the last config the admin received routes `web.localhost` to `web-<id>:8080`.
- [ ] Redeploying `web` exits 0; every config pushed along the way routed only to containers that were `running` when it arrived, and the last one routes to the new deployment.
- [ ] When the push for redeploy B fails with `AdminRequestError` message `Caddy admin API answered 500: boom`, stderr is exactly `paas: deployment <B> is running, but ingress update failed: Caddy admin API answered 500: boom` and a newline, the exit code is 1, and the previous deployment is still `running` with its container running.
- [ ] The same failure with `--json` prints one JSON line whose `status` is `running` and whose `id` is B, and gives the same stderr and exit code 1.
- [ ] With ingress up, `paas stop web` prints `stopped web (deployment <id>)`, exits 0, and the last pushed config has no route; when that push fails, stdout still has the `stopped` line, stderr is `paas: web is stopped, but ingress update failed: <message>`, and the exit code is 1.
- [ ] Without `paas ingress up`, deploy and stop of `web` exit 0 and the admin received no config.
- [ ] `tests/deploy-cli.test.ts` and `tests/status-logs-cli.test.ts` pass unchanged.
