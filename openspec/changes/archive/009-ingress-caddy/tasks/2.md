## Context

Contract: "Admin API on loopback only", "Config generation", "TLS modes", "Admin client" and "Ingress status" (route parsing only) in the `ingress` delta. This is a new folder, `src/ingress/`.

`desiredRoutes` reads the store only through `listApps` in `src/state/apps.ts` and `deploymentHistory` in `src/state/deployments.ts`, which is newest first, so the newest running deployment is the first with status `running`. Build the upstream with `containerName` from `src/deployments/types.ts`. `TlsMode` comes from `src/state/settings.ts`.

The config for TLS mode `off` and one route is exactly this, and mode `auto` differs only in `"listen":[":443"]` and no `automatic_https` key:

```json
{"admin":{"listen":"0.0.0.0:2019"},"apps":{"http":{"servers":{"paas":{"listen":[":80"],"automatic_https":{"disable":true},"routes":[{"match":[{"host":["web.localhost"]}],"handle":[{"handler":"reverse_proxy","upstreams":[{"dial":"web-abc123:8080"}]}],"terminal":true}]}}}}}
```

`routesFromConfig` reads that shape back from whatever `GET /config/` returned: it takes `apps.http.servers.paas.routes`, and each route's first host and first upstream `dial`. It never throws; anything missing or of the wrong type gives no route, and `null` gives `[]`.

`HttpCaddyAdmin` uses the global `fetch`. `load` sends `POST <base>/load` with `Content-Type: application/json`. `getConfig` sends `GET <base>/config/` and returns the parsed JSON. When `fetch` itself rejects, throw `AdminUnreachableError` with `<cause>` taken from the rejection's `cause.code`, or else its message. Both error classes extend one `IngressError` base and set `name` to the class name.

`FakeCaddyAdmin` is the test double every later task uses. `load` first takes the next error from `failures`, if any, and rejects with it. Otherwise it awaits `onLoad`, if set, records the config in `loads`, and makes it the value `getConfig` returns. `getConfig` returns `null` before any successful load.

Test `HttpCaddyAdmin` against a `node:http` server on `127.0.0.1` port 0, started in the test. Get a refused port by listening and then closing a server. No other network use.

## Acceptance
- [ ] `buildCaddyConfig("off", [{ hostname: "web.localhost", upstream: "web-abc123:8080" }])` deep-equals the JSON in Context; in mode `auto` the server listens on `[":443"]` and has no `automatic_https` key; `admin.listen` is `0.0.0.0:2019` in both.
- [ ] Routes come out ordered by hostname whatever the input order, and an empty route list gives `"routes":[]`.
- [ ] `desiredRoutes` on a store where `web` (hostname `web.localhost`, port 8080) has running deployments A then B returns one route to `web-<B id>:8080`; apps without a hostname, or with no `running` deployment, get none. Tests may seed deployments with `createDeployment` and `setDeploymentStatus`.
- [ ] `routesFromConfig(buildCaddyConfig(mode, routes))` returns `routes` sorted by hostname for both modes; `null`, `{}` and a route without `match` give no route and do not throw.
- [ ] `HttpCaddyAdmin.load` sends `POST /load` with `Content-Type: application/json` and the config as its body; `getConfig` sends `GET /config/` and returns the parsed body.
- [ ] A 400 with body `{"error":"bad config"}` rejects with `AdminRequestError`, `status` 400, message `Caddy admin API answered 400: {"error":"bad config"}`; a refused port rejects with `AdminUnreachableError` whose message starts `cannot reach Caddy admin API at http://127.0.0.1:<port>: `.
- [ ] `FakeCaddyAdmin` rejects with each queued failure in order, then records loads in `loads`, awaits `onLoad` before recording, and `getConfig` returns the last recorded config, or `null` before any.
