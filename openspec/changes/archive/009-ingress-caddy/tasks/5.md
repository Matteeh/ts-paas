## Context

Contract: "Ingress command group", "Ingress up command", "Ingress down command" and "Ingress status command" in the `cli` delta.

`CommandContext` in `src/commands/context.ts` gains an optional admin factory, and `buildProgram` in `src/program.ts` gains a matching `admin` option. Export `getAdmin(context)`, which returns the injected client or `new HttpCaddyAdmin(DEFAULT_ADMIN_URL)`; task 6 uses it from `deploy` and `stop`. Keep every existing export and behavior of both files.

Register the group the way `registerAppsCommand` in `src/commands/apps.ts` does, with the subcommands in `src/commands/ingress.ts`. Each subcommand runs inside `runAction` and `withEngine`, then calls `ingressUp`, `ingressDown` or `ingressStatus` from `src/ingress/caddy.ts` with the engine deps plus `admin: getAdmin(context)`. Parse `--http-port` and `--https-port` with `parsePort` from `src/commands/format.ts`. Pass `--tls` through, because `setIngressSettings` validates it, and `runAction` turns its `ValidationError` into a usage error. Print status through `writeOutput` in `src/output.ts`, with labels padded as `formatDoctor` in `src/commands/doctor.ts` does.

Tests build the program in-process with `buildProgram(io, { env, runtime, clock, admin })`, a temporary `PAAS_HOME`, one `FakeRuntime` and one `FakeCaddyAdmin`, as `tests/deploy-cli.test.ts` does. Copy its helpers; do not import from it. Tests may seed apps and running deployments with `src/state` functions on the same `state.db`.

## Acceptance
- [ ] `paas ingress` alone exits 2 and stderr contains `Usage: paas ingress`, `up`, `down` and `status`; each subcommand has a one-line description.
- [ ] `paas ingress up` with no apps prints exactly `ingress is up (created): http 80, https 443, tls off, routes 0` and exits 0; running it again prints `ingress is up (unchanged): ...`.
- [ ] `paas ingress up --http-port 8080 --https-port 8443 --tls auto` prints `ingress is up (created): http 8080, https 8443, tls auto, routes 0`, and a later bare `paas ingress up` keeps those values and prints `(unchanged)`.
- [ ] `--tls on`, `--http-port abc` and `--http-port 0` each exit 2 with stderr starting `paas: `, and leave no `paas-caddy` container and the default settings.
- [ ] With app `web` (hostname `web.localhost`, port 8080) seeded with a running deployment, `paas ingress up` prints `routes 1`, and `paas ingress status` prints `caddy:    running`, `tls:      off`, `http:     80`, `https:    443`, `routes:   1`, `  web.localhost -> web-<id>:8080`.
- [ ] Before any up, `paas ingress status` prints the five lines of the "Status without Caddy" scenario, and `--json` prints `{"caddy":"missing","tls":"off","httpPort":80,"httpsPort":443,"routes":null}`.
- [ ] `paas ingress down` prints `removed paas-caddy; kept volume paas-caddy-data`, then `paas-caddy does not exist`, both exiting 0; `tests/cli.test.ts` and `tests/doctor-cli.test.ts` pass unchanged.
