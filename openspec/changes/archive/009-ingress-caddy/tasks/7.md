## Context

Contract: the `ingress` delta as a whole, against a real engine. Follow `tests/integration/docker.itest.ts`: without `PAAS_INTEGRATION=1`, register one test named `ingress integration` with `skip: "set PAAS_INTEGRATION=1 to run"` and do nothing else. The task's `verify` runs only that branch, and the change-level `pnpm verify` typechecks the file; the real run is a human step.

With the variable set, the test must never touch a real `paas-caddy`, so it uses its own target, `{ container: "paas-test-caddy", volume: "paas-test-caddy-data", adminPort: 12019 }`, HTTP port 18080, HTTPS port 18443, and `new HttpCaddyAdmin("http://127.0.0.1:12019")`. It builds a `DockerRuntime` on the resolved socket with labels `{ "paas.test": "true" }`, opens `openStore(":memory:")` with `systemClock`, and creates app `whoami` with image `docker.io/traefik/whoami:v1.11.0`, port 80 and hostname `whoami.localhost`. It then calls `ingressUp` with those ports and runs `deploy` with an `onRunning` hook that calls `syncIngress` with the same deps. Both images must stay fully qualified, because Podman does not resolve short names.

Fetch with `node:http` `request` to `127.0.0.1:18080` with a `Host` header, so the test does not depend on name resolution. Retry for up to 10 seconds, every 500 ms, until the response is 200. `traefik/whoami` answers with lines that include `Hostname: `. `after` calls `runtime.removeLabelled({ "paas.test": "true" })`, even when the test fails. Give the test a 120-second timeout.

In `docs/integration-testing.md`, add a section "Ingress test". Say what it pulls (`docker.io/library/caddy:2`, `docker.io/traefik/whoami:v1.11.0`), the host ports it binds (18080, 18443, and 12019 on `127.0.0.1`), that it leaves a real `paas-caddy` alone, and the Podman 3.4 `dnsname` plugin caveat from the proposal's human steps. Leave the "Known results" table as it is.

## Acceptance
- [ ] Without `PAAS_INTEGRATION`, `node --import tsx --test tests/integration/ingress.itest.ts` reports one skipped test and exits 0, and `pnpm test:integration` runs both itest files.
- [ ] With the variable set, the test deploys `whoami`, asserts its status is `running`, and gets a 200 whose body contains `Hostname: ` for `Host: whoami.localhost`.
- [ ] The same request with `Host: other.localhost` gets a body without `Hostname: `.
- [ ] Everything the test creates carries `paas.test=true` and is removed in `after`; the test uses no name, volume or port of the default target.
- [ ] `docs/integration-testing.md` has the "Ingress test" section with the images, ports and the Podman 3.4 `dnsname` caveat, and its "Known results" table is unchanged.
- [ ] `pnpm verify` passes, which typechecks the new file.
