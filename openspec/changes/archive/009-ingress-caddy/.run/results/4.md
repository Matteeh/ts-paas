## Changed

- `src/deployments/engine.ts`: added the optional `onRunning` field to `DeployOptions`. Moved the running hook and `replacePrevious` outside the `try` that fails a deployment, so a rejected hook no longer reaches the cleanup/`failed` catch. `deploy` now awaits `onRunning` once with the new `running` record, then calls `replacePrevious`, then resolves.
- `tests/deploy-hook.test.ts`: new test file covering the hook running once before replacement, the progress order, a rejected hook keeping both deployments running, a first deploy with and without a hook, and the hook not firing on health or pull failure.
