## Changed

- Added `src/ingress/caddy.ts` with `CADDY_IMAGE`, `IngressTarget`, `DEFAULT_TARGET`, `IngressDeps`, `UpAction`, `UpResult`, `IngressStatus`, `ingressUp`, `ingressDown`, `syncIngress` and `ingressStatus`.
  - `ingressUp` stores settings first (so an invalid value fails with `ValidationError` before any runtime call), then creates, starts, recreates or leaves `paas-caddy` based on existence and the `paas.ingress.http-port`/`paas.ingress.https-port` labels, then pushes `buildCaddyConfig` with `desiredRoutes`, retrying only `AdminUnreachableError` every 250 ms up to 40 times.
  - Container spec matches the contract: `docker.io/library/caddy:2`, `paas-net`, `unless-stopped`, `CADDY_ADMIN=0.0.0.0:2019`, the three ingress labels, HTTP/HTTPS published on `""` (every host) and 2019 only on `127.0.0.1`, and the volume at `/data`.
  - `ingressDown` stops with `DEFAULT_STOP_TIMEOUT_SECONDS` and removes the container, keeping the volume, and resolves `false` when missing. `syncIngress` pushes once only while the container runs. `ingressStatus` reports `missing`/`stopped`/`running` with stored settings and reads routes via `routesFromConfig` only while running.
- Added `tests/ingress-caddy.test.ts` with a `RecordingRuntime` subclass of `FakeRuntime`, a `FakeClock`, `FakeCaddyAdmin` and an in-memory store, covering every acceptance line.
