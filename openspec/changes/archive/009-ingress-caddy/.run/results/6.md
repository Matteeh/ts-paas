## Changed

- `src/commands/deploy.ts`: `deploy` now receives an `onRunning` hook that calls `syncIngress` with the engine deps plus `getAdmin(context)`. The hook records the running record and any ingress error; when `deploy` rejects with that hook's error, the command prints the running JSON record when `--json` is set and throws `deployment <id> is running, but ingress update failed: <message>`. `AppNotFoundError` and `DeploymentInProgressError` still pass through, and a failed deployment still prints its record/last log lines.
- `src/commands/stop.ts`: after `stopApp` returns and the `stopped <app> (deployment <id>)` line is printed, `syncIngress` is called. A rejection throws `<app> is stopped, but ingress update failed: <message>`.
- `tests/ingress-deploy-cli.test.ts`: new in-process CLI tests. Covers the successful deploy push and route upstream, a redeploy whose every pushed config routes only to containers that were running at push time (an `onLoad` hook inspecting each upstream), a failed redeploy push keeping both deployments and containers running (human and `--json`, exact stderr and exit 1), a stop pushing an empty route set, a failed push after stop keeping the `stopped` line, and deploy/stop without ingress pushing no config.
