## Changed

- Added `tests/integration/ingress.itest.ts`. Without `PAAS_INTEGRATION=1` it registers one skipped test named `ingress integration`. With the variable set it builds a `DockerRuntime` on the resolved socket with labels `{ "paas.test": "true" }`, opens `openStore(":memory:")`, creates app `whoami` (`docker.io/traefik/whoami:v1.11.0`, port 80, hostname `whoami.localhost`), brings ingress up on its own target `{ container: "paas-test-caddy", volume: "paas-test-caddy-data", adminPort: 12019 }` with HTTP port 18080 and HTTPS port 18443 and a `HttpCaddyAdmin("http://127.0.0.1:12019")`, and runs `deploy` with an `onRunning` hook that calls `syncIngress`. It asserts the deployment is `running`, then requests `127.0.0.1:18080` over `node:http` with `Host: whoami.localhost`, retrying every 500 ms for up to 10 s until a 200 whose body contains `Hostname: `, and checks `Host: other.localhost` is not routed to it. The test has a 120-second timeout and an `after` that calls `runtime.removeLabelled({ "paas.test": "true" })`.
- Added an `## Ingress test` section to `docs/integration-testing.md`, naming the two pulled images, the bound host ports (18080, 18443 and 12019 on `127.0.0.1` only), that it leaves a real `paas-caddy` alone, and the Podman 3.4 `dnsname` plugin caveat. The "Known results" table is untouched.
