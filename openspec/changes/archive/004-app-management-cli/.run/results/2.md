## Changed

- `src/program.ts`: `buildProgram` now takes `(io, options: { env?: NodeJS.ProcessEnv })`, defaulting to `process.env`, and calls `registerAppsCommand(program, { io, env })`. Everything else is unchanged.
- `src/commands/apps.ts`: `registerAppsCommand` adds the `apps` group (`manage apps`) and registers the five subcommands through their own registration functions.
- `src/commands/apps-create.ts`: `create <name>` with required `--image`/`--port`, optional `--host`, repeatable `--env` (`collect`), `--json`. Parses port/env inside `runAction`+`withStore`, creates the app, prints the masked `AppView` via `writeOutput`.
- `src/commands/apps-list.ts`: `list` with `--json`; builds rows (`name, image, port, hostname, status, createdAt, updatedAt`, no env) from `listApps` + `latestDeployment`, prints `no apps`/`[]` when empty, otherwise a `formatTable` table.
- `src/commands/apps-show.ts`: `show <name>` with `--reveal`/`--json`, prints the `AppView` masked unless revealed.
- `src/commands/apps-set.ts`: `set <name>` with `--image`, `--port`, `--host`, `--unset-host`, repeatable `--env`/`--unset-env`, `--json`. Rejects no change, host conflict and same-key set/unset with `failUsage`; merges the environment from the current app and passes it whole to `updateApp`; prints like `create`.
- `src/commands/apps-delete.ts`: `delete <name>` deletes through the store and prints `deleted app <name>`.
- `tests/apps-cli.test.ts`: covers every acceptance line — group wiring and help, the tsx child-process `apps list` run (asserting `state.db` appears), create storage/masking/JSON/duplicate/missing-option, the four validation usage errors and that they store nothing, list human/JSON/empty/dashes/order and no `env`, show mask/reveal/JSON/not-found, set merge/port-only/unset-host/conflict messages/host-in-use, and delete success/running refusal.
