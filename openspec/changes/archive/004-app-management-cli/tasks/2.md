## Context

Reuse, without editing:
- From `src/commands/context.ts`: `CommandContext`, `withStore`, `runAction`, `failUsage`.
- From `src/commands/format.ts`: `toAppView`, `formatAppDetails`, `formatTable`, `parseEnvPairs`, `parsePort`, `collect`, `MASK`.
- `writeOutput` and `processIo` from `src/output.ts`.
- From `src/state/`: `createApp`, `getApp`, `listApps`, `updateApp`, `deleteApp`, `latestDeployment`, and (tests only) `openStore`, `stateDbPath`, `createDeployment`, `setDeploymentStatus`.

No dependency changes; there is no network. `tests/cli.test.ts` is frozen and must keep passing.

Each subcommand lives in its own file and exports `registerAppsCreate(apps, context)` (and so on), taking the `apps` `Command` and the `CommandContext`. `src/commands/apps.ts` exports `registerAppsCommand(program: Command, context: CommandContext): void`. It adds the `apps` group with description `manage apps` and registers the five subcommands, whose descriptions are `create an app`, `list apps`, `show one app`, `change an app` and `delete an app`.

`buildProgram(io = processIo, options: { env?: NodeJS.ProcessEnv } = {})` calls `registerAppsCommand(program, { io, env: options.env ?? process.env })`. Keep everything else in `src/program.ts` as it is.

Every action wraps its body in `runAction(command, ...)`, where `command` is the subcommand (commander passes it as the action's last argument). It opens the store with `withStore` and parses `--port` with `parsePort` and `--env` with `parseEnvPairs` inside that wrapper. Repeatable options use `collect` with no default, so help shows none. `create` uses `requiredOption` for `--image` and `--port`. `create`, `show` and `set` print `writeOutput(io, view, { json }, formatAppDetails)`. `set` rejects no change, `--host` with `--unset-host`, or a key in both `--env` and `--unset-env` with `failUsage` and the messages `nothing to change`, `--host and --unset-host conflict`, and `KEY is both set and unset`. When `--env` or `--unset-env` is given, `set` passes the merged environment to `updateApp`.

Tests build `buildProgram(io, { env: { PAAS_HOME: <temp dir> } })` with a capturing `Io` for each command and call `run`. They seed deployments with `openStore(stateDbPath(env))`, `createDeployment` and `setDeploymentStatus`, closing the store before running a command.

## Acceptance
- [ ] Wiring: `paas apps` alone writes `Usage: paas apps` and all five subcommand names to `err` and returns 2; the help of `paas apps --help` lists each subcommand with its description; a child process running `src/cli.ts apps list` through `tsx` with `PAAS_HOME` set to a temporary directory prints `no apps` and exits 0, and `state.db` exists there afterwards.
- [ ] `create web --image nginx:1 --port 80 --host Web.Localhost --env A=x=y --env A=z` returns 0, stores host `web.localhost` and env `{A: "z"}`, and prints the masked details (`  A=******`); `--json` prints the masked `AppView` as one line; a second create returns 1 with `err` exactly `paas: app "web" already exists\n`; a missing `--image` returns 2.
- [ ] Validation: `--port 0` returns 2 with `err` starting `paas: invalid port 0` then containing `Usage: paas apps create`, and `out` empty; `--port abc` gives `paas: invalid port "abc"`, `--env NOEQ` gives `paas: invalid --env "NOEQ": expected KEY=VALUE`, and name `Web` gives `paas: invalid app name "Web"`, each returning 2 and storing nothing.
- [ ] `list` with no apps prints `no apps\n`, and `--json` prints `[]\n`; with apps `web` (latest deployment `running`) and `api` (none), it prints the header `NAME  IMAGE  PORT  HOST  STATUS` aligned by `formatTable` with `api` before `web`, and `-` for missing host and status; `--json` prints an array of `{name, image, port, hostname, status, createdAt, updatedAt}` without `env`.
- [ ] `show web` masks every env value in the human form and with `--json`; `--reveal` shows the values in both forms; `show nope` returns 1 with `paas: app "nope" not found`.
- [ ] `set web --env B=3 --env C=4 --unset-env A` on env `{A: "1", B: "2"}` stores `{B: "3", C: "4"}`; `--port 81` changes only the port; `--unset-host` clears the host; `set web` alone, `--host x.localhost --unset-host`, and `--env A=1 --unset-env A` each return 2 with the contracted message; a host used by another app returns 1.
- [ ] `delete web` prints `deleted app web\n`, returns 0, and removes it; with a seeded `running` deployment it returns 1 with `err` exactly `paas: app "web" has a running deployment; stop the app first\n` and `web` still exists.
