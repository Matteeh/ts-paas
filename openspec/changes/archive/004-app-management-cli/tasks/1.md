## Context

Task 2 builds the five `paas apps` subcommands on these helpers and never edits them, so write the signatures below exactly.

Reuse: `Io` from `src/output.ts`; `UsageError` from `src/errors.ts`; `buildProgram` and `run` from `src/program.ts` (tests only; do not edit it); `openStore` and `Store` from `src/state/db.ts`; `stateDbPath` from `src/state/paths.ts`; `ValidationError` from `src/state/errors.ts`; `App` from `src/state/apps.ts`; `Deployment` and `DeploymentStatus` from `src/state/deployments.ts`. Do not edit any of them. No dependency changes; there is no network.

`failUsage` uses commander's `command.error(message, { exitCode, code })`. It prints through the program's `outputError`, which `buildProgram` already rewrites from a leading `error: ` to `paas: `, and shows the command's help after it because `showHelpAfterError` is inherited by subcommands. `run` turns the resulting `CommanderError` into exit code 2. Test it by adding a throwaway subcommand to `buildProgram(io)` with a capturing `Io` and calling `run` with that program, as `tests/cli.test.ts` does.

`formatAppDetails` label lines: each label (`name:`, `image:`, `port:`, `host:`, `status:`, `created:`, `updated:`) is padded with spaces to 9 characters and followed by the value, `-` for `null`. Then `env:` alone followed by one `  KEY=VALUE` line per variable sorted by key, or `env:     -` when there are none. Lines are joined with `\n` with no trailing newline.

## Ports

```ts
// src/commands/context.ts
export interface CommandContext { io: Io; env: NodeJS.ProcessEnv }
export function withStore<T>(context: CommandContext, fn: (store: Store) => T | Promise<T>): Promise<T>; // openStore(stateDbPath(context.env)); close in finally
export function failUsage(command: Command, message: string): never; // command.error(`error: ${message}`, { exitCode: 2, code: "paas.usage" })
export function runAction(command: Command, fn: () => void | Promise<void>): Promise<void>; // ValidationError or UsageError from fn → failUsage(command, error.message); anything else rethrown

// src/commands/format.ts
export const MASK = "******";
export interface AppView {
  name: string; image: string; port: number; hostname: string | null;
  status: DeploymentStatus | null; env: Record<string, string>; createdAt: string; updatedAt: string;
}
export function toAppView(app: App, latest: Deployment | null, options: { reveal: boolean }): AppView; // env values become MASK unless reveal
export function formatAppDetails(view: AppView): string;
export function formatTable(headers: readonly string[], rows: readonly (readonly string[])[]): string; // left-aligned, two spaces between columns, trailing spaces trimmed, "\n"-joined, no trailing newline
export function parseEnvPairs(values: readonly string[]): Record<string, string>; // split at first "="; later value wins; UsageError `invalid --env "<value>": expected KEY=VALUE` when no "=" or empty key
export function parsePort(value: string): number; // /^\d+$/ else UsageError `invalid port "<value>"`
export function collect(value: string, previous: string[] | undefined): string[]; // commander reducer for repeatable options
```

## Acceptance
- [ ] `withStore` with `env` `{ PAAS_HOME: <temp dir> }` passes a store for `<temp dir>/state.db`, returns `fn`'s result, and closes the store both after success and when `fn` throws (the error propagates); a later `withStore` on the same env sees data written by an earlier one.
- [ ] Through `run`, a subcommand `probe` whose action is `runAction(cmd, () => { throw new ValidationError("port", "invalid port 0") })` makes `err` start with `paas: invalid port 0`, then contain `Usage: paas probe`, leaves `out` empty, and returns 2; the same holds for a thrown `UsageError`.
- [ ] Through `run`, a `probe` action that throws `new AppExistsError("web")` inside `runAction` makes `err` exactly `paas: app "web" already exists\n` and returns 1.
- [ ] `toAppView` copies the app's fields, takes `status` from `latest` (`null` when none), and masks every env value as `******` unless `reveal` is true; `formatAppDetails` produces exactly the label lines described in Context, including `-` for a missing host and status and `env:     -` for an empty env.
- [ ] `formatTable(["NAME", "PORT"], [["web", "80"], ["a", "8080"]])` returns `NAME  PORT\nweb   80\na     8080`, with no trailing spaces on any line.
- [ ] `parseEnvPairs(["A=x=y", "B=", "A=z"])` returns `{ A: "z", B: "" }`; `["A"]` and `["=x"]` throw `UsageError` with the contracted message; `parsePort("80")` is 80 and `parsePort("abc")`, `parsePort("8.5")` and `parsePort("")` throw `UsageError` `invalid port "<value>"`; `collect("b", ["a"])` is `["a", "b"]` and `collect("a", undefined)` is `["a"]`.
