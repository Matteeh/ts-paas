## Changed

- `src/commands/context.ts`: added `explainError(error)`. For a `PortInUseError` with an address it returns `host port <address> is already in use; find what holds it with "ss -ltnp | grep :<port>" (on rootless Podman ...)`, with `<port>` taken after the address's last `:`. For a `null` address it returns `a host port is already in use (<first line of message>); find what holds it with "ss -ltnp" (...)`. Anything else returns the error's message. `runAction` now rethrows a `PortInUseError` as `new Error(explainError(error))`; every other branch is unchanged.
- `src/commands/reconcile.ts`: added `start-ingress` to `ReportItem`'s kind union and to `formatReconcileItem` as `start-ingress: paas-caddy (<detail>)`. `readCaddyRoutes` now reports a `state` of `running | stopped | missing` instead of a boolean. In `runReconcile`, when Caddy is `stopped` it adds one `start-ingress` item via a new `startIngressItem` helper: `planned`/`ok: null` in a dry run, otherwise `ingressUp` with no changes, reporting `started, <n> routes`/`ok: true` or `failed: <first line of explainError>`/`ok: false`. The `push-ingress` block is skipped. `running` and `missing` behave as before.
- `tests/ingress-resilience-cli.test.ts`: new tests built in-process with a `FakeRuntime`, `FakeClock` and `FakeCaddyAdmin` (helpers copied from `tests/reconcile-cli.test.ts`). A `PortInUseRuntime extends FakeRuntime` throws a `PortInUseError` for `paas-caddy` while its `busy` flag is set. Covers: reconcile starting a stopped Caddy and pushing its route; the dry-run human and JSON item with all-null ids; the `paas status` drift warning and `nothing to reconcile` with no Caddy; reconcile reporting a busy-port start failure, exiting 1 and pushing nothing; `paas up` on a fresh busy fake printing the exact one-line message and leaving no Caddy; `explainError` for an address, a `null` address and a plain error.
