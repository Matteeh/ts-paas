## Changed

- `src/ingress/caddy.ts`: wrapped `startContainer` in `createCaddy` with a try/catch. On failure it force-removes the container it just created (`removeContainer(id, { force: true })`), swallows any error from that removal, and rethrows the original start error. The existing-stopped-container "started" path in `ingressUp` is untouched, so an existing `paas-caddy` that fails to start is left in place.
- `tests/ingress-start-failure.test.ts`: new tests copied from the helpers in `tests/ingress-caddy.test.ts` (not imported). `FailingRuntime extends FakeRuntime` toggles `failStart` (rethrows a single `PortInUseError` object, `name`/`address` intact) and `failRemove` (throws a distinct removal error), and the five tests cover all acceptance lines: new container start failure cleans up and rejects with the same object with no admin config, failed cleanup still surfaces the start error, a retry after failure reports `created` and runs the container, a preexisting exited container is left in place on start failure, and a failed recreate leaves no `paas-caddy`.
