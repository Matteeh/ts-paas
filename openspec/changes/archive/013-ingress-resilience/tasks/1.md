## Context

Contract: "Typed runtime errors" and "Busy host ports" in the `container-runtime` delta.

Add `PortInUseError` to `src/runtime/errors.ts` next to the other subclasses. It has a readonly `address: string | null`, and the constructor takes the message, the address and `{ cause }`. `name` must be `PortInUseError`, as the base class already arranges.

In `mapError` in `src/runtime/docker.ts`, for kinds `create` and `container` (which `startContainer` uses), check the engine message before the create-only name-conflict rule. The name-conflict rule matches `already in use`, which `address already in use` also contains. A message containing `address already in use`, `port is already allocated` or `ports are not available` (case-insensitive) becomes `PortInUseError`, keeping the message and `cause`. Take the address from the first match of these, in order:
- `listen tcp <host>:<port>`
- `Bind for <host>:<port>`
- `exposing port TCP <host>:<port>`

`<host>` is an IPv4 address or `[...]` for IPv6. With no match, the address is `null`.

The real messages, recorded on 2026-09-24:
- Podman 3.4.4: `rootlessport listen tcp 0.0.0.0:38080: bind: address already in use`
- Docker Engine 24.0.7: `driver failed programming external connectivity on endpoint paas-caddy (b9ac2b2e...): Bind for 0.0.0.0:8080 failed: port is already allocated`
- Docker Desktop on WSL 2: `Ports are not available: exposing port TCP 127.0.0.1:2019 -> 0.0.0.0:0: listen tcp 127.0.0.1:2019: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.`

`tests/docker-runtime.test.ts` and `tests/docker-engine-fixes.test.ts` are frozen and must pass unchanged. The change-level `pnpm verify` runs them. Write the new tests with a stub client like the `DockerStub` in `tests/docker-engine-fixes.test.ts`. Copy the pattern; do not import from that file. No test contacts a real engine.

- [ ] `startContainer` rejects with `PortInUseError` for each of the three recorded messages as a 500, with `address` `0.0.0.0:38080`, `0.0.0.0:8080` and `127.0.0.1:2019`; `message` is the engine message and `cause` the original error.

- [ ] A 500 `address already in use` with no address in it gives `PortInUseError` with `address` `null`.
- [ ] A 500 on create ending `that name is already in use` is still `NameConflictError`, and a 500 `disk full` on start is still a plain `RuntimeError`.
- [ ] `new PortInUseError("m", "1.2.3.4:5").name` is `PortInUseError`, and it is an instance of `RuntimeError`.
