## Context

Contract: "Rootless Podman 3.4 limits" in the `container-runtime` delta, and "Reconcile starts a stopped Caddy" in the `cli` delta.

`docs/manual-testing.md` step 3, "Caddy restarts and forgets its routes", tells readers to run `docker restart paas-caddy`. On rootless Podman 3.4, restarting a running container fails with `rootlessport listen tcp ...: bind: address already in use` and leaks a port forwarder. Rewrite the step so its commands work on both engines:
- Docker: keep `docker restart paas-caddy`.
- Podman: use `podman kill --signal KILL paas-caddy`. Caddy stays `Exited (137)` because rootless Podman 3.4 ignores restart policies. `paas status` warns about 1 item, and `paas reconcile` prints `start-ingress: paas-caddy (started, 1 routes)` and restores the route.

Keep the rest of the step's shape, and its "Check" note about Caddy's default page.

Add a section "Podman 3.4 port forwarders" before "Recording results". Say that a container the `podman` command started or restarted can leave a `containers-rootlessport` process holding its host ports after it is gone. paas itself never starts containers that way. Say how to confirm and fix it:
- `ss -ltnp | grep :<port>` shows `users:(("exe",pid=<pid>,...))`;
- `tr '\0' ' ' < /proc/<pid>/cmdline` prints `containers-rootlessport`;
- `podman ps -a` shows no container using the port;
- then `kill <pid>`.

Mention that on WSL 2, Windows relays these ports, so a leaked forwarder also blocks Docker Desktop, which reports `Ports are not available`. Keep the rest of the file unchanged.

In `README.md`, in the "Quickstart" section's rootless Podman subsection, add one sentence: rootless Podman 3.4 does not restart a crashed Caddy, so run `paas reconcile` to bring it back. Link to the new section of `docs/manual-testing.md` for busy ports. Change nothing else in the README.

The new `tests/docs-podman.test.ts` is an offline hygiene test that reads both files as text with `node:fs`, like `tests/contract-hygiene.test.ts`.
