## Context

Contract: "Reconcile starts a stopped Caddy" and "Busy host port message" in the `cli` delta.

**Busy-port message.** Add an exported `explainError(error: unknown): string` to `src/commands/context.ts`. For a `PortInUseError` (from `src/runtime/errors.ts`), it returns the text in the `cli` delta: `<port>` is the part of `address` after its last `:`, and a `null` address uses the fallback wording. For anything else, it returns the error's message. In `runAction`, rethrow a `PortInUseError` as `new Error(explainError(error))`, so `run` in `src/program.ts` prints it as an operation failure. This covers `paas up`, `paas ingress up`, `paas deploy` and every other command without touching them. Keep every other behavior of `runAction`.

**Stopped Caddy in reconcile.** In `runReconcile` in `src/commands/reconcile.ts`, the ingress step already reads `ingressStatus`. When it reports `stopped`, which also covers a `paas-caddy` stuck in `created`, add one `start-ingress` item and skip the `push-ingress` logic:
- In a dry run, the detail is `planned` and `ok` is `null`.
- Otherwise, call `ingressUp` from `src/ingress/caddy.ts` with no changes. It starts the container and pushes with retries. The detail is `started, <n> routes` with `n = result.routes.length`, and `ok` is `true`. On failure, the detail is `failed: <first line of explainError(error)>` and `ok` is `false`.

The item has `app`, `deploymentId`, `containerId` and `name` set to `null`, and prints as `start-ingress: paas-caddy (<detail>)`. Add `"start-ingress"` to `ReportItem`'s `kind` union. When Caddy is `running` or `missing`, the ingress step behaves as today. `paas status` needs no change: its drift check counts dry-run items.

`tests/reconcile-cli.test.ts`, `tests/reconcile-redeploy-cli.test.ts`, `tests/status-drift-cli.test.ts` and `tests/commands-runtime.test.ts` are frozen and must pass unchanged. The change-level `pnpm verify` runs them.

Tests build the program in-process as `tests/reconcile-cli.test.ts` does, with one `FakeRuntime`, a `FakeClock` and a `FakeCaddyAdmin`. Copy its helpers; do not import from it. Stop Caddy with `runtime.stopContainer("paas-caddy")` after `paas ingress up`. For busy ports, subclass `FakeRuntime` in the test file so that `startContainer` throws a `PortInUseError` for `paas-caddy` while a flag is set.

## Acceptance
- [ ] With ingress up and `web` (hostname `web.localhost`) running, after `paas-caddy` is stopped, `paas reconcile` prints exactly `start-ingress: paas-caddy (started, 1 routes)`, exits 0, `paas-caddy` runs, and the admin's latest config routes `web.localhost`; no `push-ingress` line appears.
- [ ] `paas reconcile --dry-run` with Caddy stopped prints `start-ingress: paas-caddy (planned)` and leaves it stopped; `--json` gives an item of kind `start-ingress`, `ok` `null`, and `null` for `app`, `deploymentId` and `containerId`.
- [ ] With Caddy stopped and nothing else wrong, `paas status` prints `paas: warning: state and engine disagree on 1 item(s); run paas reconcile --dry-run` to stderr; with no `paas-caddy` at all, reconcile prints `nothing to reconcile`.
- [ ] When starting the stopped Caddy throws `PortInUseError` for `127.0.0.1:2019`, reconcile prints `start-ingress: paas-caddy (failed: host port 127.0.0.1:2019 is already in use; find what holds it with "ss -ltnp | grep :2019" ...)`, exits 1, and pushes nothing.
- [ ] `paas up` on a fresh fake whose Caddy start throws that error exits 1, stderr is exactly the one-line message from the `cli` delta for `127.0.0.1:2019` and a newline, and no `paas-caddy` exists.
- [ ] `explainError` with a `null` address returns `a host port is already in use (<first line of message>); find what holds it with "ss -ltnp" (...)`; for a plain `Error("boom")` it returns `boom`.
