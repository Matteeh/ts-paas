## Changed

- `src/runtime/docker.ts` (new): `DockerRuntime` implements `ContainerRuntime` over dockerode 4 on a Unix socket, and is the only module that imports dockerode. Constructing it never connects. It maps:
  - `ping` via `version()`: `docker` unless a component is named `Podman Engine`, then `podman`, with `version`, `apiVersion` and `endpoint: socketPath`.
  - `pullImage` via `pull(ref)` + `modem.followProgress`; resolves only on `onFinished`, rejects on a stream error or an output event carrying `error`/`errorDetail`; 404 and Podman 500 "manifest unknown"/"does not exist"/"access denied" become `ImageNotFoundError`, any other 500 a plain `RuntimeError`.
  - `createContainer` body with `name`, `Image`, `Env`, `Labels` (spec + runtime labels + `paas.managed=true`), `ExposedPorts`, `HostConfig.RestartPolicy`, `PortBindings`, `Binds` (`:ro` when read-only) and `NetworkMode`; 404 → `ImageNotFoundError`, 409 → `NameConflictError`.
  - start/stop mapping 304 to success, 404 to `ContainerNotFoundError`; `stop` passes `{ t }`; `remove` passes `{ force }` and leaves a 409 as a plain `RuntimeError`.
  - `inspectContainer`/`listContainers` mapping state (`created`; `running`/`restarting`/`paused` → running; the rest → exited), `null` for zero timestamps and non-exited exit codes, leading `/` stripped and `RestartCount`.
  - `containerLogs` requests `since` in floored seconds without `tail`, otherwise `tail` (or `"all"`), demuxes with `demuxDockerLogs` using `Config.Tty` and applies `filterLogs`.
  - `ensureNetwork`/`ensureVolume` create only after a 404 inspect, treat a 409 on create as success and pass the runtime labels; `networkExists` is `true` on inspect and `false` on 404.
  - `removeLabelled` force-removes matching containers, then networks, then volumes, ignoring 404s.
  - Socket errors (`code` without `statusCode`) become `RuntimeUnavailableError` `cannot reach container engine at <socket>: <code>`; typed errors keep the engine message and the original error as `cause`.
- `tests/docker-runtime.test.ts` (new): a hand-written `DockerStub` cast to the client, with one test per acceptance line (ping/docker/podman/no-connect, pull flow and error mapping, create body/409/404, start/stop/remove, inspect/list/logs, ensure/networkExists/removeLabelled, socket codes, package script).
- `tests/integration/docker.itest.ts` (new): skips one test unless `PAAS_INTEGRATION=1`, otherwise resolves the socket and registers `runtimeContract("docker (<socket path>)", ...)` with `registry.k8s.io/pause:3.10`, a missing image, `paas.test=true` labels and an `after` teardown.
- `package.json`: added `scripts["test:integration"]` exactly `node --import tsx --test "tests/integration/**/*.itest.ts"`. No other script or dependency changed.

## Deviated

- The task text said published ports use `"<port>/tcp"`; the adapter uses the port's `protocol` and defaults to `tcp`. The acceptance case has no protocol, so the emitted body is unchanged, and this keeps the interface's optional `protocol` meaningful.
- `removeContainer` always sends `{ force }` (`false` when unspecified) rather than sending no option; the acceptance only asserts that `force` is passed.
