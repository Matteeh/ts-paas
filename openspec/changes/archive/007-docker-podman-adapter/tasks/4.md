## Context

The default runtime factory in `src/commands/context.ts` changes from "no runtime configured" to the Docker adapter. Two preexisting tests assert the old message, so `tests.modify` covers exactly `tests/commands-runtime.test.ts` and `tests/deploy-cli.test.ts`. Change only the assertions about the default factory and the no-runtime message in them, and keep every other test in those files as it is. `tests/cli.test.ts`, `tests/commands-helpers.test.ts` and `tests/status-logs-cli.test.ts` are frozen and must keep passing. No dependency changes; there is no network.

**No test may contact a real engine.** The developer's machine may run Docker. Every test that reaches the default factory must set `PAAS_SOCKET` to a path in a temporary directory: either a missing path, or an existing regular file when it only constructs the runtime without calling it. That includes child processes, which get a copied `process.env` with `PAAS_SOCKET` overridden.

Reuse, without editing:
- `DockerRuntime` from `src/runtime/docker.ts` and `resolveSocket` from `src/runtime/socket.ts`.
- `RuntimeUnavailableError` from `src/runtime/errors.ts`.
- `PAAS_NETWORK` from `src/deployments/types.ts`.
- `runAction` and `writeOutput`.
- `FakeRuntime` and `FakeClock`.

Drop `NO_RUNTIME_MESSAGE`; nothing else may reference it afterwards. `withEngine` calls `getRuntime`, awaits `runtime.ping()`, and only then opens the store. `paas doctor` uses `getRuntime` directly, never the store, and never calls `ensureNetwork`. Its description is `check the container engine`. `buildProgram` registers it after the existing commands and changes nothing else.

## Acceptance
- [ ] `defaultRuntimeFactory({ PAAS_SOCKET: <existing temp file> })` returns a `DockerRuntime` whose `socketPath` is that file, without contacting it; with `PAAS_SOCKET` set to a missing path it throws `RuntimeUnavailableError` `cannot reach container engine at <path>: socket not found`.
- [ ] `withEngine` rejects with `RuntimeUnavailableError` without calling `fn` or creating `state.db` when `PAAS_SOCKET` is missing and no runtime is injected, and when the injected fake has `unavailable = true` (because of the ping); with a working fake it behaves as before.
- [ ] In `tests/commands-runtime.test.ts`, only the assertions about the default factory and `NO_RUNTIME_MESSAGE` change to the new behavior; in `tests/deploy-cli.test.ts`, the child-process `deploy web` runs with a missing `PAAS_SOCKET` and asserts stderr exactly `paas: cannot reach container engine at <path>: socket not found\n`, exit 1, and `status` still exits 0 with status `-`.
- [ ] `paas doctor` on an injected fake prints exactly `socket:   -\nengine:   fake 0.0.0\napi:      -\npaas-net: missing\n` and returns 0; after `ensureNetwork("paas-net")` on that fake, the last line is `paas-net: present`; `--json` prints `{"socket":null,"engine":"fake","version":"0.0.0","apiVersion":null,"paasNet":false}`.
- [ ] `paas doctor` on a wrapped fake whose `ping` also returns `apiVersion: "1.47"` and `endpoint: "/tmp/x.sock"` prints `socket:   /tmp/x.sock` and `api:      1.47`; it never calls `ensureNetwork`.
- [ ] A child process running `src/cli.ts doctor` through `tsx` with `PAAS_HOME` set to a temporary directory and a missing `PAAS_SOCKET` exits 1 with stderr exactly `paas: cannot reach container engine at <path>: socket not found\n`, and `state.db` does not exist afterwards.
- [ ] Help lists `doctor` with its description, and `grep`-level: no source file under `src/` references `NO_RUNTIME_MESSAGE` or `no container runtime is configured yet`.
