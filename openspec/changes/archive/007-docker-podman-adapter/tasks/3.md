## Context

`dockerode` 4.0.12 and `@types/dockerode` 4.0.1 are already installed by a human. Do not add, remove, or change any dependency, and do not touch `pnpm-lock.yaml`. In `package.json`, change only `scripts`. There is no network, and no test may contact a real engine.

`src/runtime/docker.ts` is the only file that imports dockerode: `import Docker from "dockerode"`, which works under `nodenext`. Reuse, without editing:
- `resolveSocket` from `src/runtime/socket.ts`.
- `demuxDockerLogs` and `filterLogs` from `src/runtime/docker-logs.ts`.
- The errors from `src/runtime/errors.ts`.
- `MANAGED_LABEL` and the types from `src/runtime/types.ts`.
- `runtimeContract` from `tests/support/runtime-contract.ts`.

Tests pass a hand-written stub as `client` (cast with `as unknown as Docker`). The stub records calls and returns canned responses or throws errors shaped like dockerode's: an `Error` with `statusCode` and `json: { message }`, or a socket error with `code` such as `ECONNREFUSED`, `ENOENT` or `EACCES`.

dockerode 4 calls to use:
- `version()` for `ping`. Podman lists a component named `Podman Engine`; read `Version` and `ApiVersion`.
- `pull(ref)` plus `modem.followProgress(stream, onFinished)`. An `error` or `errorDetail` field in any output event is a failure.
- `createContainer(body)` and `getContainer(idOrName)` with `start`, `stop({ t })`, `remove({ force })`, `inspect()`, and `logs({ follow: false, stdout: true, stderr: true, timestamps: true, tail, since })`, which resolves to a Buffer.
- `listContainers({ all: true, filters: { label: ["k=v", ...] } })`.
- `getNetwork(name).inspect()`, `createNetwork({ Name, Driver: "bridge", Labels })`, `listNetworks({ filters })`.
- `getVolume(name).inspect()`, `createVolume({ Name, Labels })`, `listVolumes({ filters })`.

Mapping:
- **Create body:**
  - `name`, `Image`, `Env: ["K=V"]`, `Labels` (the spec's labels plus the `labels` option plus `paas.managed=true`).
  - `ExposedPorts` for the internal port and every published port as `"<port>/tcp"`.
  - `HostConfig.RestartPolicy.Name`, `HostConfig.PortBindings` (`HostIp`, `HostPort` as a string), `HostConfig.Binds` as `volume:path` with `:ro` when read-only, and `HostConfig.NetworkMode` set to the network.
- **Inspect:**
  - The name is `Name` without its leading `/`; the image is `Config.Image`; the labels are `Config.Labels`.
  - State: `created` → `created`; `running`, `restarting` and `paused` → `running`; `exited`, `dead` and `removing` → `exited`.
  - `exitCode` is `State.ExitCode` when exited, otherwise `null`.
  - `StartedAt` and `FinishedAt` of `0001-01-01T00:00:00Z` become `null`.
  - `restartCount` is `RestartCount`.
  - List summaries map the same way, using `Names[0]` and `State`.
- **Logs:**
  - With `since`, request `since` in whole seconds (floored) and no `tail`, then apply `filterLogs`.
  - Without `since`, request `tail` (or `"all"`).
  - The TTY flag comes from `Config.Tty` on inspect.
- **Errors:** follow the `Engine error mapping` and `Docker and Podman differences` requirements exactly. Any error with a `code` and no `statusCode` is a socket error and becomes `RuntimeUnavailableError` naming the socket path.

`removeLabelled(labels)` force-removes every container carrying all the labels, then every such network, then every such volume, ignoring 404s.

The integration test: when `process.env.PAAS_INTEGRATION !== "1"`, it registers one test skipped with `set PAAS_INTEGRATION=1 to run`. Otherwise it resolves the socket and calls `runtimeContract("docker (<socket path>)", factory)`, where the factory returns:
- `runtime`: a `DockerRuntime` with `labels: { "paas.test": "true" }`.
- `images`: `{ present: "registry.k8s.io/pause:3.10", missing: "docker.io/library/paas-contract-missing-image:0" }`.
- `teardown`: `removeLabelled({ "paas.test": "true" })`.

It also runs that cleanup in an `after` hook.

## Acceptance
- [ ] `ping` returns `{ name: "docker", version, apiVersion, endpoint: socketPath }` from a Docker-shaped `version()` and `name: "podman"` when a component is named `Podman Engine`; constructing a `DockerRuntime` makes no client call.
- [ ] `pullImage` resolves only after `followProgress` finishes; an output event with `error` rejects; a 404 rejects with `ImageNotFoundError`; a 500 with message `manifest unknown`, `... does not exist` or `... access denied` rejects with `ImageNotFoundError`; any other 500 rejects with a plain `RuntimeError`.
- [ ] `createContainer` sends the exact body described in Context for a spec with env, labels, network, internal port, restart policy, one published port and one read-only volume, and returns the created id; 409 → `NameConflictError`; 404 → `ImageNotFoundError`.
- [ ] Start and stop map 304 to success and 404 to `ContainerNotFoundError`; `stopContainer` passes `t`; `removeContainer` passes `force`, and a 409 there is a `RuntimeError` that is not a `NameConflictError`; `inspectContainer` maps every state, the zero timestamps, the leading `/` and `RestartCount` as described.
- [ ] `listContainers` sends `all: true` with one `label` filter entry per label and maps summaries; `containerLogs` demultiplexes a stubbed Buffer, requests `since` in seconds and applies millisecond `since` and `tail` after it, and treats `Config.Tty: true` as one stdout stream.
- [ ] `ensureNetwork` and `ensureVolume` create only after a 404 inspect, treat a 409 on create as success, and pass the `labels` option; `networkExists` is `true` on inspect and `false` on 404; `removeLabelled` removes containers, then networks, then volumes carrying every label.
- [ ] Socket errors `ECONNREFUSED`, `ENOENT`, `EACCES` and `ENOTSOCK` reject with `RuntimeUnavailableError` `cannot reach container engine at <socket>: <code>`; `package.json` has `scripts["test:integration"]` exactly `node --import tsx --test "tests/integration/**/*.itest.ts"`, and `tests/integration/docker.itest.ts` reports one skipped test and exits 0 without `PAAS_INTEGRATION`.
