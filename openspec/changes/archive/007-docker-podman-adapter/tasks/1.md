## Context

This task changes the interface that task 3's `DockerRuntime` implements, and fixes the contract suite so it can later run against a real engine. `tests.modify` covers only the two preexisting test files in scope: `tests/support/runtime-contract.ts` and `tests/clock.test.ts`. `tests/runtime-fake.test.ts` is frozen and must keep passing; its `ping` assertion expects exactly `{ name: "fake", version: "0.0.0" }`. No dependency changes; there is no network.

Contract suite changes:
1. Add a test that `networkExists` of a fresh run-unique name is `false`, and `true` after `ensureNetwork`.
2. The inspect test must check that the given labels and `paas.managed=true` are present, instead of comparing the whole labels object, because a real engine or harness may add labels.
3. The list test must replace the shared keys `x` and `y` with label keys unique to the run (for example, built from a random suffix created once per `runtimeContract` call), so it never matches containers the suite did not create.

Keep every other contract test as it is.

`tests/clock.test.ts` has a flaky assertion: `systemClock.sleep(5)` measured with `Date.now()` can report 4 ms. Measure with `performance.now()` and accept any elapsed time of at least 4 ms. Leave its other tests unchanged.
