## Context

Contract: "Drift warning" and "Status overview" in the `cli` delta.

In `src/commands/status.ts`, after the command has printed its normal output, both forms (`paas status` and `paas status <app>`, human and `--json`) run a drift check inside the same `withStore` call. The check gets the runtime with `getRuntime(context)`, pings it, and calls `runReconcile` from `src/commands/reconcile.ts` with `{ dryRun: true, prune: false, redeploy: false }`, the store, the context clock and `admin: getAdmin(context)`. When the report has items, it writes `paas: warning: state and engine disagree on <n> item(s); run paas reconcile --dry-run` and a newline with `context.io.err`. Any error thrown anywhere in the check, including the synchronous one `getRuntime` throws when the socket cannot be resolved, is swallowed without output. The check never changes stdout or the exit code. An unknown app still fails before any check.

`tests.modify` covers only one test in `tests/status-logs-cli.test.ts`, "status prints the aligned overview with uptime and dashes". It seeds a running deployment whose container does not exist in the fake, so the warning now appears. Change only its `assert.equal(result.err, "")` to expect exactly the warning with 1 item. Change nothing else in that file. The frozen child-process test in `tests/deploy-cli.test.ts`, "status still exits 0" with a missing `PAAS_SOCKET`, must pass unchanged and proves the unreachable case.

Do not edit `src/commands/reconcile.ts` or any file outside `scope`. The new `tests/status-drift-cli.test.ts` builds the program in-process as `tests/status-logs-cli.test.ts` does, with one `FakeRuntime`, a `FakeClock` and a `FakeCaddyAdmin`. Copy the helpers; do not import from it.
