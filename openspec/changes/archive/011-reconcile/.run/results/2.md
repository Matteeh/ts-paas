## Changed

- Added `src/commands/reconcile.ts`:
  - `ReportItem`, `ReconcileReport`, `runReconcile`, `formatReconcile(Item)` and `registerReconcile`.
  - `runReconcile` plans with `planReconcile`, applies with `applyReconcile` unless `dryRun`, turns plan items into report items (`fail`, `orphan`/`prune`), adds one `redeploy` per app whose container failed and that has no running deployment left (never for stuck failures), then reads `ingressStatus` and adds a `push-ingress` item and calls `syncIngress` when Caddy runs and something changed or the routes differ. It prints nothing.
  - `registerReconcile` registers `paas reconcile` with `--dry-run`, `--prune`, `--redeploy`, `--json`, prints the report with `writeOutput`, and throws `reconcile had <n> failed item(s)` when any item has `ok === false`.
- `src/program.ts`: imported `registerReconcile` and called it after `registerDoctor`. Nothing else changed.
- Added `tests/reconcile-cli.test.ts` (helpers copied from `tests/ingress-deploy-cli.test.ts`): nothing-to-do, help listing, disappeared container, dry-run with `--prune --redeploy`, `--redeploy` after a lost container, stuck deployment not redeployed, orphan report/`--prune`/failed removal, Caddy lost routes and no-op repush, fail-then-ingress push, and `--dry-run --json` with the applied `--json` item.

## Missing context

- The `ReportItem` port has no field for the container name, but the human line is `orphan: <name> ...` / `prune: <name> ...`. To keep the JSON item at exactly the six documented fields, the name is carried in a module-level `WeakMap<ReportItem, string>` populated by `runReconcile` and read by the formatter. The interface is unchanged.
