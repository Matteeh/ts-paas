## Changed

- Added `src/deployments/reconcile.ts`:
  - `DEFAULT_STUCK_AFTER_MS = 600_000`, `ReconcileItem`, `ReconcileOutcome`.
  - `planReconcile` compares `listApps`/`deploymentHistory` with `listContainers({ [MANAGED_LABEL]: "true" })`, fails running deployments whose container is missing/null or not running (`container disappeared` / `container exited with code <n>` / `container is not running`), fails `pending`/`pulling`/`starting` deployments past the stuck threshold (`stuck in <status> since <at>`), then reports `paas.app`-labelled containers that no staying deployment owns as orphans. Failures sort by app name, orphans by container name. It mutates nothing.
  - `applyReconcile` marks each failure `failed`, force-removes orphans only with `prune` (treating `ContainerNotFoundError` as removed), reports them otherwise, and keeps going after a failed removal.
- Added `tests/reconcile-plan.test.ts` covering each acceptance line: agreement with an empty plan, missing/null/exited/created containers, stuck thresholds (default, exact, custom), orphans (`replaced` leftovers, failed deployments' containers, in-flight containers, caddy without `paas.app`), ordering, and apply with/without `prune` including a failing removal.
