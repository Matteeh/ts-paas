## Changed

- `src/commands/status.ts`: added `warnDrift(store, context)`, called after normal output in both `paas status` and `paas status <app>`, inside the same `withStore` call. It gets the runtime with `getRuntime`, pings it, and calls `runReconcile(..., { dryRun: true, prune: false, redeploy: false })` with the store, the context clock and `getAdmin(context)`. When the report has items it writes `paas: warning: state and engine disagree on <n> item(s); run paas reconcile --dry-run` plus a newline to `context.io.err`. The whole check is wrapped in `try/catch` that swallows every error, so an unreachable engine prints nothing extra and the check never changes stdout or the exit code. An unknown app still throws from `getApp` before output or check.
- `tests/status-drift-cli.test.ts` (new): one `FakeRuntime`, one `FakeClock` and one `FakeCaddyAdmin`, helpers copied from `tests/status-logs-cli.test.ts`. Covers a healthy container with empty stderr; a disappeared container warning `1 item(s)` while stdout stays the table and state stays `running`; `status --json` and `status web --json` producing byte-identical stdout to the healthy state plus the warning; an orphan plus a disappeared container warning `2 item(s)`; and `runtime.unavailable = true` printing the table with empty stderr and exit 0 while `status nope` still fails with the unknown-app error.
- `tests/status-logs-cli.test.ts`: the single assertion named in Context, in "status prints the aligned overview with uptime and dashes", now expects the one-item warning instead of empty stderr.
