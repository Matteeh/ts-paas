## Changed

- Added `src/deployments/engine.ts` with `DeployOptions` and `deploy`. The flow reads the app, refuses a concurrent deploy, creates the deployment and reports it, pulls the image, ensures `paas-net`, creates the container with the specified name/labels/network/port/env/restart policy, records `starting` with the container id, starts it, and runs `checkHealth`. Unhealthy containers are force-removed and the deployment fails with `healthFailureMessage`; healthy ones move to `running`, after which every other running deployment of the app is stopped/removed and marked `replaced`. Any other error after creation fails the deployment with the runtime message after a best-effort force-remove of the new container. Progress is reported once per recorded status change, including the replaced one.
- Added `tests/deploy-engine.test.ts` covering every acceptance line: happy path (status order, created spec, managed label), redeploy replacement ordering, health failure with the last 20 log lines, pull failure, name conflict, start failure with container cleanup, concurrent deploy, unknown app, failed previous removal reported in the replaced message, and out-of-band removal counting as removed.

## Deviated

- The test helper casts `deps.clock` to `FakeClock` to call `advance`; `EngineDeps.clock` is the `Clock` interface, so this is a test-only widening, not a behavior change.
