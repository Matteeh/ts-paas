## Changed

- Added `src/deployments/stop.ts` with `StopOptions` and `stopApp`. It reads the app (rejecting with `AppNotFoundError` when unknown), finds the app's `running` deployment (rejecting with `AppNotRunningError` when there is none), stops and force-removes that deployment's container using `options.stopTimeoutSeconds ?? DEFAULT_STOP_TIMEOUT_SECONDS`, treating `ContainerNotFoundError` from either call as already removed and letting any other error propagate so the deployment stays `running`, then marks the deployment `stopped` and reports it once through `onProgress`.
- Added `tests/deploy-stop.test.ts` covering every acceptance line: the happy stop (status, `finishedAt`, container gone, exactly one `stopped` progress event), default/explicit stop timeout forwarding, `AppNotRunningError` for no deployment / a failed deployment / an already stopped deployment, `AppNotFoundError` for an unknown app, out-of-band container removal still resolving `stopped`, a failing `stopContainer` propagating and leaving the deployment running with its container present, and a redeploy after a stop leaving the stopped deployment `stopped` rather than `replaced`.
