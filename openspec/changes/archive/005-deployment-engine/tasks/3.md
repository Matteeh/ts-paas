## Context

Reuse, without editing:
- From `src/deployments/types.ts`: `EngineDeps`, `containerName`, `DEFAULT_STOP_TIMEOUT_SECONDS`.
- `AppNotRunningError` from `src/deployments/errors.ts`.
- `deploy` from `src/deployments/engine.ts`, to reach a running deployment in tests.
- From `src/state/`: `getApp`, `deploymentHistory`, `setDeploymentStatus`, `getDeployment`, `createApp`, `openStore`.
- `ContainerNotFoundError` and `RuntimeError` from `src/runtime/errors.ts`.
- `FakeRuntime` and `FakeClock`.

No SQL outside `src/state/`. No dependency changes; there is no network.

`stopApp` does the following:
1. Calls `getApp`, which rejects with `AppNotFoundError` for an unknown app.
2. Finds the app's `running` deployment with `deploymentHistory`. With none, it rejects with `AppNotRunningError`.
3. If the deployment has a container id, calls `stopContainer` with `options.stopTimeoutSeconds ?? DEFAULT_STOP_TIMEOUT_SECONDS`, then `removeContainer` with `force`. It treats `ContainerNotFoundError` from either as removed and lets any other error propagate, leaving the deployment `running`.
4. Marks the deployment `stopped` and calls `deps.onProgress` with status `stopped` and a non-empty message.
5. Resolves with the stopped deployment.

Tests reach a running deployment the way the engine tests do: they share one `FakeClock` and start `deploy` without awaiting. Then `await new Promise((resolve) => setImmediate(resolve))`, `await clock.advance(3000)`, and await the result. No test sleeps in real time. To inject a failure, wrap the `FakeRuntime` in a test object implementing `ContainerRuntime` that delegates every other method.

## Acceptance
- [ ] Stopping `web` with a running deployment resolves with that deployment `stopped` with `finishedAt` set, its container no longer exists, and `onProgress` received one `stopped` event for it.
- [ ] Stopping an app with no deployments, or whose only deployment is `failed` or already `stopped`, rejects with `AppNotRunningError`; an unknown app rejects with `AppNotFoundError`.
- [ ] If the container was removed out of band, stopping still resolves `stopped`.
- [ ] A wrapped `stopContainer` that throws `RuntimeError("busy")` makes `stopApp` reject with that error, and the deployment is still `running` with its container still present.
- [ ] After a stop, a new `deploy` of the same app becomes `running`, and the stopped deployment stays `stopped`, not `replaced`.
