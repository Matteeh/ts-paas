## Context

Tasks 2 and 3 build the deploy flow and stop on these files and never edit them, so write the signatures below exactly.

Reuse, without editing: `Clock` and `FakeClock` from `src/clock.ts`; `ContainerRuntime` and its types from `src/runtime/types.ts`; `FakeRuntime` from `src/runtime/fake.ts`; `RuntimeError` from `src/runtime/errors.ts`; `Store` from `src/state/db.ts`; `DeploymentStatus` from `src/state/deployments.ts`. No dependency changes; there is no network.

`checkHealth` inspects the container right after it is called. If it is not `running`, the result is unhealthy at once, without sleeping. Otherwise it remembers `startedAt`, sleeps `windowMs` on the clock (skipped when `windowMs` is 0), and inspects again. It is healthy only when the state is `running`, `restartCount` is 0, and `startedAt` is unchanged. When unhealthy, it reads the last `HEALTH_LOG_LINES` log entries and keeps their `text`. Reasons: `container exited with code <n>` when exited, `container restarted during the health window` when running but restarted, and `container is not running (state <state>)` otherwise. Runtime errors propagate.

`FakeClock.advance` resolves only sleeps already registered. In tests, start `checkHealth` without awaiting it, then `await new Promise((resolve) => setImmediate(resolve))` so it reaches its sleep, then `await clock.advance(...)`, then await the result. Tests must not sleep in real time. For restart detection, wrap a `FakeRuntime` in a test object implementing `ContainerRuntime` that delegates every method and overrides `inspectContainer`'s `restartCount`. Every error class sets `this.name = new.target.name` in `DeployError`.

## Acceptance
- [ ] A running unscripted container is healthy after `advance(3000)` with a 3000 ms window, and the promise is still pending after `advance(2999)`; with window 0 it is healthy without any `advance`.
- [ ] A container scripted to exit with code 3 and no delay is unhealthy without any `advance`: `reason` `container exited with code 3`, `exitCode` 3.
- [ ] A container scripted to exit with code 1 after 1000 ms is unhealthy after `advance(3000)` with a 3000 ms window; one exiting after exactly 3000 ms is unhealthy; one exiting after 3001 ms is healthy.
- [ ] A wrapped runtime reporting `restartCount` 1 at the end of the window gives `reason` `container restarted during the health window`.
- [ ] An unhealthy container that wrote 25 scripted log lines returns exactly the last 20 texts in order; `healthFailureMessage({ reason: "r", logs: ["a", "b"] })` is `r\na\nb`, and with no logs it is `r`.
- [ ] A `RuntimeError` from `inspectContainer` rejects `checkHealth` with that error.
- [ ] The constants and `containerName("web", "abc123") === "web-abc123"` hold; `DeploymentInProgressError` and `AppNotRunningError` are `instanceof DeployError` with `name` equal to their class names and the messages above.
