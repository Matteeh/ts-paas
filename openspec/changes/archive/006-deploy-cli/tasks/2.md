## Context

Follow the registration pattern of `src/commands/apps-show.ts`. Each command file exports `registerDeploy(program, context)`, `registerStatus`, `registerLogs` or `registerStop`, and its action runs inside `runAction`. Descriptions: `deploy an app`, `show deployment status`, `print an app's logs`, `stop an app`.

`buildProgram(io = processIo, options: { env?: NodeJS.ProcessEnv; runtime?: () => ContainerRuntime; clock?: Clock } = {})` builds the context `{ io, env: options.env ?? process.env, runtime: options.runtime, clock: options.clock }`. It passes that context to `registerAppsCommand` and the four new registrations. Keep everything else in `src/program.ts` as it is. `tests/cli.test.ts` is frozen and must keep passing.

Reuse, without editing:
- From `src/commands/context.ts`: `withEngine`, `withStore`, `contextClock`, `runAction`.
- From `src/commands/deploy-helpers.ts`: `parseDuration`, `parseTail`, `formatUptime`, `shortContainerId`.
- `formatTable` from `src/commands/format.ts` and `writeOutput` from `src/output.ts`.
- `deploy` from `src/deployments/engine.ts`, `stopApp` from `src/deployments/stop.ts`, and `AppNotRunningError` from `src/deployments/errors.ts`.
- From `src/state/`: `getApp`, `listApps`, `updateApp`, `latestDeployment`, `deploymentHistory`, `deploymentStatusChanges`.

No SQL outside `src/state/`. No dependency changes; there is no network.

Behavior:
- **deploy** runs everything inside `withEngine`. With `--image`, it calls `updateApp` first. Human mode passes an `onProgress` that writes `<status>: <message>\n` to `io.out`; `--json` passes none. When the result is `running`, it prints `<app> is running (deployment <id>)`, or the record with `--json`. When it is `failed`, it prints each error line after the first as `  | <line>` in human mode, or the record with `--json`, then throws `new Error("deployment <id> failed: <first line>")`.
- **status** uses `withStore` only, never the runtime. `uptimeSeconds` and `runningSince` come from the time of the latest `running` status change, compared with `contextClock(context).now()`. The one-app form prints its overview row as a table, a blank line, then the deployments table.
- **logs** uses `withEngine`. It finds the `running` deployment in `deploymentHistory`; with none it throws `new AppNotRunningError(app)`. `--since` becomes `new Date(clock.now() - parseDuration(value))`.
- **stop** uses `withEngine` and `stopApp`, then prints `stopped <app> (deployment <id>)`.

Tests build `buildProgram(io, { env: { PAAS_HOME: <temp dir> }, runtime: () => fake, clock })` for each command, with one `FakeRuntime({ clock, scripts })` and one `FakeClock` shared across a test's commands. They create apps with `run(["apps", "create", ...])`. `FakeClock.advance` resolves only sleeps already registered. For a deploy, start `run([...])` without awaiting, then `await new Promise((resolve) => setImmediate(resolve))`, then `await clock.advance(3000)`, then await the exit code. If one `setImmediate` is not enough, flush twice. No test sleeps in real time. The child-process tests spawn `process.execPath --import tsx src/cli.ts` with `PAAS_HOME` set to a temporary directory.

## Acceptance
- [ ] Wiring: help lists `deploy`, `status`, `logs` and `stop` with their descriptions; in a child process, after `apps create web --image nginx:1 --port 80`, `deploy web` exits 1 with stderr exactly `paas: no container runtime is configured yet\n` and `status` exits 0 showing `web` with status `-`.
- [ ] `deploy web` prints lines starting `pending: `, `pulling: `, `starting: `, `running: ` in order, then `web is running (deployment <id>)`, and returns 0 with the container running in the fake; a redeploy also prints a `replaced: ` line; `--image nginx:2` updates the app first and the new deployment uses `nginx:2`; `--json` prints exactly one line, a JSON record with status `running`.
- [ ] A deploy whose image is scripted to write 25 log lines and exit with code 3 prints `  | <line>` for exactly the last 20, returns 1 with `err` exactly `paas: deployment <id> failed: container exited with code 3\n`, and leaves the previous deployment running; `--json` prints one JSON line with status `failed` and returns 1; `--image "a b"` returns 2.
- [ ] `status` prints the header `APP  STATUS  CONTAINER  IMAGE  UPTIME` aligned by `formatTable`, rows ordered by name, with the 12-character container id and `2m 5s` of uptime after the clock advances 125 s past `running`, and `-` for an app without deployments; with no apps it prints `no apps`; `--json` prints the contracted array.

- [ ] `stop web` prints `stopped web (deployment <id>)`, returns 0 and removes the container; a second `stop web` returns 1 with `err` exactly `paas: app "web" has no running deployment\n`.
