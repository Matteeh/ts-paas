## Ports

```ts
// src/commands/context.ts (additions)
export interface CommandContext {
  io: Io;
  env: NodeJS.ProcessEnv;
  runtime?: () => ContainerRuntime; // default defaultRuntimeFactory
  clock?: Clock;                    // default systemClock
}
export const NO_RUNTIME_MESSAGE = "no container runtime is configured yet";
export function defaultRuntimeFactory(): ContainerRuntime; // throws new Error(NO_RUNTIME_MESSAGE)
export function contextClock(context: CommandContext): Clock; // context.clock ?? systemClock
// withStore now opens the store with { clock: contextClock(context) }
export function withEngine<T>(context: CommandContext, fn: (deps: EngineDeps) => T | Promise<T>): Promise<T>;
// calls the runtime factory first, before opening the store; then withStore; deps = { store, runtime, clock: contextClock(context) } without onProgress

// src/commands/deploy-helpers.ts
export function parseDuration(value: string): number; // /^(\d+)(s|m|h|d)$/ → milliseconds; else UsageError `invalid duration "<value>": use a number followed by s, m, h or d`
export function parseTail(value: string): number;     // /^[1-9]\d*$/; else UsageError `invalid tail "<value>"`
export function formatUptime(ms: number): string;     // floor; < 60 s "Ns"; < 1 h "Nm Ns"; < 1 d "Nh Nm"; else "Nd Nh"
export function shortContainerId(id: string | null): string | null; // first 12 characters
```

## Acceptance
- [ ] `tests/commands-helpers.test.ts` still passes unchanged, and a `CommandContext` of just `{ io, env }` typechecks.
- [ ] `withStore` with a `FakeClock` in the context stores times from that clock: an app created inside it has `createdAt` equal to `clock.now().toISOString()`; without a clock it uses `systemClock`.
- [ ] `withEngine` with `runtime: () => fake` and a `FakeClock` passes deps whose `runtime` is `fake`, whose `clock` is that clock, and whose `store` reads the same `state.db` as `withStore`; the store is closed afterwards, also when `fn` throws.
- [ ] `withEngine` without a `runtime` rejects with `Error(NO_RUNTIME_MESSAGE)` before opening the store: no `state.db` is created in a fresh `PAAS_HOME`, and `fn` is not called.
- [ ] Through `run`, a probe subcommand whose action calls `withEngine` without a runtime inside `runAction` makes `err` exactly `paas: no container runtime is configured yet\n` and returns 1.
- [ ] `parseDuration` gives 30000 for `30s`, 300000 for `5m`, 7200000 for `2h`, 86400000 for `1d`, and throws `UsageError` with the contracted message for `5x`, `m`, `1.5h` and ``; `parseTail` gives 1 for `1` and 20 for `20`, and throws `UsageError` `invalid tail "<value>"` for `0`, `-1`, `abc` and ``.
- [ ] `formatUptime` gives `0s` for 0, `45s` for 45999, `3m 20s` for 200000, `2h 5m` for 7500000 and `4d 3h` for 356400000; `shortContainerId` cuts to 12 characters, keeps shorter ids, and passes `null` through.
