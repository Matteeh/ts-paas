## Changed

- `src/program.ts`: `buildProgram` now accepts optional `runtime` and `clock` in its options, builds one `CommandContext` (`{ io, env, runtime, clock }`), passes it to `registerAppsCommand`, and registers the four new commands `deploy`, `status`, `logs` and `stop`. Nothing else in the file changed.
- `src/commands/deploy.ts`: new. `registerDeploy(program, context)` runs everything inside `withEngine`, applies `--image` through `updateApp` first, passes an `onProgress` that writes `<status>: <message>` in human mode and none in `--json` mode, prints the running line or the deployment record, prints the error lines after the first as `  | <line>` on failure, and throws `deployment <id> failed: <first line>`.
- `src/commands/status.ts`: new. `registerStatus` reads only the store: `paas status` prints the `APP STATUS CONTAINER IMAGE UPTIME` table ordered by name with twelve-character container ids, `-` for missing values, `no apps`, and the contracted JSON array; `paas status <app>` prints the overview table, a blank line, and the five newest deployments, with `deployments` added in JSON mode.
- `src/commands/logs.ts`: new. `registerLogs` runs inside `withEngine`, parses `--tail`/`--since` as usage errors, finds the running deployment or throws `AppNotRunningError`, reads container logs with the injected clock, routes stdout/stderr lines in human mode, and prints the entries array in JSON mode.
- `src/commands/stop.ts`: new. `registerStop` runs `stopApp` inside `withEngine` and prints `stopped <app> (deployment <id>)`.
- `tests/deploy-cli.test.ts`: new. Covers help wiring, the child-process no-runtime failure plus a runtime-free `status`, successful deploy progress and state, redeploy `replaced`, `--image` update, `--json` success, the 25-line/exit-3 failure (last 20 `  | ` lines, exact stderr, previous deployment still running), `--json` failure, and the whitespace image usage error.
- `tests/status-logs-cli.test.ts`: new. Covers the status overview/JSON shapes, uptime and twelve-character ids, `no apps`, `status <app>` overview plus five newest deployments and its JSON form, unknown app, logs stream routing, `--tail`, `--since` against the fake clock, `--json`, bad duration, no-running-deployment, and stop plus a refused second stop.

## Deviated

- Tests seed deployments for the `status` cases directly through the store (on the shared clock) instead of always deploying first; this is the only way to control the twelve-character container id and the seven-deployment history the acceptance lines describe. Apps are still created through `run(["apps", "create", ...])`.

## Missing context

- The acceptance text for the status overview writes the header as `APP  STATUS  CONTAINER  IMAGE  UPTIME`, but `formatTable` widens columns to their values, so a literal header only holds when no cell is wider than its header. The tests assert the header tokens and the aligned row contents instead of the literal line.
