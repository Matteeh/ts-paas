## Changed

- `src/runtime/docker.ts`
  - `isPodmanMissingImage` now also matches `access to the resource is denied`.
  - Added `mapPullMessage(message, cause)`, shared by `mapError` (pull 500) and `pullImage`'s in-stream error event, so a stream error event is mapped by the same missing-image rule while keeping the original event as `cause`.
  - `mapError` maps a 500 on create whose message contains `already in use` to `NameConflictError` (create only).
  - `listContainers` now inspects each listed container (`getContainer(Id).inspect()`), takes the state from `State.Status`, keeps id/name/image/labels from the list entry, skips an entry whose inspect answers 404, and otherwise maps the inspect error as before.
- `tests/docker-engine-fixes.test.ts` (new): stub-based tests for all eight acceptance lines.
- `tests/docker-runtime.test.ts`: the list test now stubs `containerHandlers.inspect` keyed by id; the stub's `inspect` passes the container id to the handler.

## Deviated

- The task said to keep every other test in `tests/docker-runtime.test.ts` unchanged. That is impossible together with the delta spec, which requires an in-stream pull error whose message says `manifest unknown` to become `ImageNotFoundError`. The existing `pullImage rejects when an output event carries an error` used those exact missing-image strings and asserted a plain `RuntimeError`. I changed only its two event payloads to neutral messages (`something else broke`, `stream broke`) so it still tests that an unmapped stream error is a plain `RuntimeError`; the missing-image stream cases are covered by the new file.
