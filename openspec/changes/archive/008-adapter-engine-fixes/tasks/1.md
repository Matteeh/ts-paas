## Context

Three fixes in `src/runtime/docker.ts`. Each reproduces what a real engine did in the first integration runs. No dependency changes; there is no network, and no test contacts a real engine. Write the new tests in `tests/docker-engine-fixes.test.ts` with a stub client like the `DockerStub` in `tests/docker-runtime.test.ts`. Copy the pattern; do not import from that file.

`tests.modify` covers `tests/docker-runtime.test.ts` only for the test `listContainers sends all and one label filter entry per label`. After the list fix it must also answer each listed container's `inspect` (through `stub.containerHandlers.inspect`, keyed by container id), with a `State.Status` that matches its current expectations. Keep every other test in that file unchanged, including `pullImage maps any other 500 to a plain RuntimeError`.

1. **Pull errors inside the stream.** `pullImage` currently wraps an error event from `followProgress` as a `RuntimeError`, and `mapError` returns any existing `RuntimeError` unchanged, so the message rules never run. Make the error event go through the same missing-image rule as a 500 response. Extend `isPodmanMissingImage` (rename it if you like) to also match `access to the resource is denied`. Podman's real message was `initializing source docker://paas-contract-missing-image:0: reading manifest 0 in docker.io/library/paas-contract-missing-image: errors:\ndenied: requested access to the resource is denied\nunauthorized: authentication required\n`. An error event whose message matches none of the rules stays a plain `RuntimeError`.
2. **500 name conflict on create.** Podman 3.4 answered with status 500 and `json.message` `container create: error creating container storage: the container name "x" is already in use by "9a0f...". You have to remove that container to be able to reuse that name.: that name is already in use`. On create only, a 500 whose message contains `already in use` becomes `NameConflictError`. Any other 500 on create stays a `RuntimeError`.
3. **List state from inspect.** Docker 24.0.7's `/containers/json` reported `running` right after `stop` returned, while inspect reported `exited`. `listContainers` keeps its list call and filters, then inspects every listed container (`getContainer(Id).inspect()`) and takes `state` from the inspect result, using the existing state mapping. It keeps id, name, image and labels from the list entry. It leaves out a container whose inspect answers 404, and maps any other inspect error as today.

## Acceptance

- [ ] A pull whose stream event says `something else broke` rejects with a plain `RuntimeError` that is not an `ImageNotFoundError`; a 500 response with `access to the resource is denied` rejects with `ImageNotFoundError`.
