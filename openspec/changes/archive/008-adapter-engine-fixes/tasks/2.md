## Context

Change 007 added a `declare global { interface Object { networkExists(...) } }` block to `tests/support/runtime-contract.ts`. `tsconfig.json` typechecks `src/` and `tests/` together, so that block makes every object look like it has `networkExists` in `pnpm verify`. It exists only because three deploy test files each define a `DelegatingRuntime implements ContainerRuntime` without `networkExists`. With the block removed, `tsc` reports errors only in those three files, and every error clears once each file's `DelegatingRuntime` gains a delegating `networkExists`. Subclasses such as `SpecCapturingRuntime` and `RestartCountRuntime` extend it.

`tests.modify` covers only these edits:
- `tests/support/runtime-contract.ts`: delete the `declare global` block and its comment, and add the exported `engineLabel`. Change no contract test.
- `tests/deploy-engine.test.ts`, `tests/deploy-health.test.ts`, `tests/deploy-stop.test.ts`: add `networkExists(name: string): Promise<boolean> { return this.inner.networkExists(name); }` to each `DelegatingRuntime`. Change nothing else.
- `tests/integration/docker.itest.ts`: in the `PAAS_INTEGRATION=1` branch, `await runtime.ping()` once at module level (top-level `await` works in this ESM test file), then call `runtimeContract(engineLabel(info), ...)`. The skip branch stays as it is.

Do not touch `src/`. No dependency changes; there is no network, and no test contacts a real engine. The change-level `pnpm verify` runs `tsc` after this task. It must pass without the global block, and that is the real proof.
