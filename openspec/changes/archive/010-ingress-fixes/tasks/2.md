## Context

Contract: "Integration tier" in the `container-runtime` delta.

`node --test` runs `tests/integration/docker.itest.ts` and `tests/integration/ingress.itest.ts` in parallel processes. Both build their `DockerRuntime` with labels `{ "paas.test": "true" }` and clean up with `removeLabelled({ "paas.test": "true" })`, so the contract suite's per-test teardown deleted `paas-test-caddy` during the ingress test. The fix is on the ingress side only.

`tests.modify` covers only `tests/integration/ingress.itest.ts`, and only this edit: the runtime's labels and the `removeLabelled` call in `after` both use `{ "paas.test": "ingress" }`, preferably through one module constant. Change nothing else in that file. Do not touch `tests/integration/docker.itest.ts`, `tests/support/runtime-contract.ts`, `src/` or `package.json`.

The new `tests/integration-isolation.test.ts` is an offline hygiene test like `tests/contract-hygiene.test.ts`: it reads both itest files as text with `node:fs` and checks the labels.

In `docs/integration-testing.md`, in the "Ingress test" section, change the sentence saying everything carries `paas.test=true`. It should say the ingress test labels everything `paas.test=ingress` and removes only that, so it can run in parallel with the contract suite, which uses `paas.test=true`. Change nothing else in the file.
