## Changed

- Rewrote `src/ingress/admin.ts` to use `request` from `node:http` instead of the global `fetch`. `HttpCaddyAdmin` now builds the request from the base URL with `hostname`, `port`, `path`, `method`, `headers` and `agent: false`, sends only `Content-Type: application/json` and `Content-Length` on `load`, and reads `GET /config/` with no extra headers.
- `unreachableCause` now reads the `error.code` (`ECONNREFUSED`) directly from the request `error` event and falls back to the error message, producing `cannot reach Caddy admin API at <base>: <cause>`.
- Non-2xx responses still reject with `AdminRequestError` and the first line of the body. `getConfig` returns `null` for an empty 200 body and the parsed JSON otherwise.
- Added `tests/ingress-admin-headers.test.ts` with a `node:http` server on `127.0.0.1:0` that answers 403 as Caddy 2.11.4 does when a request carries `origin`, `referer` or a `sec-fetch-*` header, records each request's header names and `content-type`, and answers 200 otherwise. Covers both success against the origin-enforcing server, the absence of browser headers with `content-type: application/json` on `load`, an empty body resolving `null`, a refused port rejecting with `AdminUnreachableError` naming `ECONNREFUSED`, a 400 rejecting with `AdminRequestError`, and that the source no longer mentions `fetch`.
