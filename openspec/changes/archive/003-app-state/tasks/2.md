## Context

Reuse `openStore` and `Store` from `src/state/db.ts`, and `ValidationError`, `AppNotFoundError`, `AppExistsError`, `HostnameInUseError` and `AppRunningError` from `src/state/errors.ts`. Do not edit those files; the v1 schema already has the `apps` and `deployments` tables. Timestamps are `store.clock.now().toISOString()`. Tests open `":memory:"` stores with a `FakeClock` from `src/clock.ts`.

The validation rules are in the `Validation` requirement of the `app-state` delta. Validators throw `ValidationError` with field `name`, `image`, `port`, `hostname` or `env`, and return the value to store (the hostname lowercased).

Map SQLite constraint failures to the typed errors: check for an existing name or hostname before writing, rather than parsing SQLite messages. `deleteApp` blocks when any row in `deployments` for the app has status `running`. Task 3 writes the deployment repository later, so `tests/state-apps.test.ts` seeds deployments with an `INSERT` through `store.db`. SQL in tests is allowed for seeding.

## Ports

```ts
// src/state/validate.ts
export function validateAppName(name: string): string;
export function validateImage(image: string): string;
export function validatePort(port: number): number;
export function validateHostname(hostname: string): string; // returns it lowercased
export function validateEnv(env: Record<string, string>): Record<string, string>;

// src/state/apps.ts
export interface App {
  name: string;
  image: string;
  port: number;
  hostname: string | null;
  env: Record<string, string>;
  createdAt: string; // ISO 8601
  updatedAt: string; // ISO 8601
}
export interface NewApp { name: string; image: string; port: number; hostname?: string | null; env?: Record<string, string> }
export interface AppChanges { image?: string; port?: number; hostname?: string | null; env?: Record<string, string> } // env replaces all; hostname null clears
export function createApp(store: Store, input: NewApp): App;
export function getApp(store: Store, name: string): App;  // AppNotFoundError when missing
export function listApps(store: Store): App[];             // ordered by name
export function updateApp(store: Store, name: string, changes: AppChanges): App;
export function deleteApp(store: Store, name: string): void;
```

## Acceptance
- [ ] `validateAppName` accepts `a`, `web-1` and a 40-character name, and rejects ``, `Web`, `1web`, `-web`, `web_1` and a 41-character name, each with `field` `name`.
- [ ] `validatePort` accepts 1 and 65535 and rejects 0, 65536 and 80.5; `validateImage` accepts `nginx:1` and `ghcr.io/a/b@sha256:abc` and rejects `` and `a b`; `validateEnv` accepts `{ A_1: "x", _b: "" }` and rejects keys `1A`, `A-B` and ``; each failure names its field.
- [ ] `validateHostname` returns `whoami.localhost` for `Whoami.Localhost` and accepts `a-b.example.com`; it rejects ``, `-a.com`, `a-.com`, `a..com`, `a.com.`, `a_b.com`, a 64-character label, and a 254-character name, with `field` `hostname`.
- [ ] `createApp` returns and stores the app with `hostname` `null` and `env` `{}` when omitted, and `createdAt` and `updatedAt` at the clock's ISO time; `getApp` returns an equal object; `listApps` orders by name; invalid input throws `ValidationError` and stores nothing.
- [ ] A duplicate name throws `AppExistsError`; a hostname used by another app throws `HostnameInUseError` on create and on update, while keeping its own hostname on update is allowed; `getApp`, `updateApp` and `deleteApp` on an unknown name throw `AppNotFoundError`.
- [ ] `updateApp` with only `port`, after the clock advances, changes the port and `updatedAt` and keeps the image, hostname, env and `createdAt`; `env` replaces the whole environment; `hostname: null` clears it; invalid changes throw `ValidationError` and change nothing.
- [ ] `deleteApp` throws `AppRunningError` and removes nothing when a seeded deployment of the app has status `running`; with only a `failed` seeded deployment it removes the app and that deployment.
