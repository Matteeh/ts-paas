## Context

Reuse `openStore` and `Store` from `src/state/db.ts`; `AppNotFoundError`, `AppRunningError`, `DeploymentNotFoundError` and `DeploymentFinishedError` from `src/state/errors.ts`; `validateImage` from `src/state/validate.ts`; and `createApp`, `getApp` and `deleteApp` from `src/state/apps.ts`. Do not edit those files. The v1 schema already has `deployments` (with `seq` for creation order) and `deployment_events`.

Ids come from `store.newId()`; times from `store.clock.now().toISOString()`. Order "latest" and history by `seq`, never by timestamp. Record the initial `pending` as the first status change. Moving to the status a deployment already has is allowed and recorded, unless it is final. Tests open `":memory:"` stores with a `FakeClock` from `src/clock.ts` and a counter-based `newId`.

## Ports

```ts
// src/state/deployments.ts
export const DEPLOYMENT_STATUSES: readonly ["pending", "pulling", "starting", "running", "failed", "stopped", "replaced"];
export type DeploymentStatus = (typeof DEPLOYMENT_STATUSES)[number];
export const FINAL_STATUSES: readonly DeploymentStatus[]; // failed, stopped, replaced
export interface Deployment {
  id: string;
  app: string;
  image: string;
  status: DeploymentStatus;
  containerId: string | null;
  error: string | null;
  createdAt: string;         // ISO 8601
  finishedAt: string | null; // ISO 8601, set on entering a final status
}
export interface StatusChange { status: DeploymentStatus; at: string }
export function createDeployment(store: Store, input: { app: string; image: string }): Deployment;
export function getDeployment(store: Store, id: string): Deployment; // DeploymentNotFoundError when missing
export function setDeploymentStatus(
  store: Store,
  id: string,
  status: DeploymentStatus,
  details?: { containerId?: string; error?: string },
): Deployment;
export function latestDeployment(store: Store, app: string): Deployment | null; // AppNotFoundError for an unknown app
export function deploymentHistory(store: Store, app: string, options?: { limit?: number }): Deployment[]; // newest first; AppNotFoundError for an unknown app
export function deploymentStatusChanges(store: Store, id: string): StatusChange[]; // oldest first
```

## Acceptance
- [ ] `createDeployment` for an existing app returns a deployment with the generated id, status `pending`, `containerId`, `error` and `finishedAt` `null`, and `createdAt` at the clock's time; `getDeployment` returns an equal object; an unknown app throws `AppNotFoundError`; an invalid image throws `ValidationError`.
- [ ] Moving a deployment pending → pulling → starting → running with the clock advancing 1000 ms before each change gives four status changes, oldest first, with times one second apart, and `finishedAt` stays `null`.
- [ ] `setDeploymentStatus` with `containerId` stores it and keeps it on later changes; moving to `failed` with `error` `exited with code 3` stores the error and sets `finishedAt` to the clock's time; `stopped` and `replaced` also set `finishedAt`.
- [ ] A deployment in `failed`, `stopped` or `replaced` rejects any further status change with `DeploymentFinishedError` and stays unchanged with no new status change; an unknown id throws `DeploymentNotFoundError` from `getDeployment`, `setDeploymentStatus` and `deploymentStatusChanges`.
- [ ] Two deployments created without the clock moving: `latestDeployment` returns the second, `deploymentHistory` lists the second then the first, and `limit: 1` returns only the second; an app with none gives `null` and `[]`; an unknown app throws `AppNotFoundError`.
- [ ] End to end through the repositories: `deleteApp` throws `AppRunningError` while a deployment is `running`; after it moves to `stopped`, `deleteApp` succeeds and `getDeployment` and `deploymentStatusChanges` for it throw `DeploymentNotFoundError`.
