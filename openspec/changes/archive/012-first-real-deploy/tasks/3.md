## Context

Contract: "End-to-end tier" in the `cli` delta.

**package.json.** Set `version` to `0.1.0`. Add the script `"test:e2e": "node --import tsx --test \"tests/e2e/**/*.e2e.ts\""`, next to `test:integration`. Change nothing else: no dependency changes, so no lockfile change. `pnpm verify` runs only `*.test.ts`, so the e2e file never runs there, but `tsc` typechecks it.

**tests/release.test.ts** is offline. It reads `package.json` and checks the version and the `test:e2e` script. It runs `paas --version` in-process through `buildProgram` and `run` from `src/program.ts`.

**tests/e2e/first-deploy.e2e.ts.** Without `PAAS_E2E=1`, register one test named `first real deploy` with `skip: "set PAAS_E2E=1 to run"`, as `tests/integration/ingress.itest.ts` does. With it set, drive the CLI in-process: for each command, `buildProgram(io, { env: { ...process.env, PAAS_HOME: <temp dir> }, runtime: () => runtime })` and `run(argv, io, program)`. Use the default admin client and the system clock. `runtime` is one `DockerRuntime` on `resolveSocket(process.env).path`, with labels `{ "paas.test": "e2e" }`, so everything the CLI creates carries that label. The `after` hook calls `runtime.removeLabelled({ "paas.test": "e2e" })` and removes the temp dir, even on failure. Before anything else, `inspectContainer("paas-caddy")`. If it exists, fail with `paas-caddy already exists; bring real paas ingress down before running the e2e test`, and touch nothing.

The flow, asserting exit code 0 at each step:
1. `up --http-port 28080 --https-port 28443`.
2. `apps create whoami --image docker.io/traefik/whoami:v1.11.0 --port 80 --host whoami.localhost --env WHOAMI_NAME=blue`.
3. `deploy whoami`.
4. GET `127.0.0.1:28080` with `Host: whoami.localhost` through `node:http` `request` (not `fetch`). Retry every 500 ms for up to 10 s until a 200. The body contains `Name: blue`.
5. `apps set whoami --env WHOAMI_NAME=green`, then `deploy whoami`. While that deploy runs, GET every 100 ms and record each status. Afterwards, every recorded status is 200, and a GET's body contains `Name: green`.
6. `logs whoami`: stdout and stderr together contain `Starting up on port 80`.
7. `stop whoami`, then `ingress down`.

Give the test a 300-second timeout.

**README.md.** Add a section "Quickstart" after "Requirements":
- install and build with `pnpm install` and `pnpm build`, then run `node dist/cli.js`, which the section shows as `paas`;
- `paas up`, create and deploy the whoami app above, and open `http://whoami.localhost` (or `curl -H "Host: whoami.localhost" http://127.0.0.1/`);
- redeploy with a changed `--env`, `paas logs`, `paas stop`, and `paas ingress down`.

Give two short subsections:
- **Docker Desktop:** the default ports work.
- **Rootless Podman on Linux:** `systemctl --user enable --now podman.socket`, `export PAAS_SOCKET=$XDG_RUNTIME_DIR/podman/podman.sock`, and the low-port caveat. Either run `sudo sysctl net.ipv4.ip_unprivileged_port_start=80`, or `paas up --http-port 8080 --https-port 8443` and add `:8080` to URLs.

Explain that browsers and most resolvers send `*.localhost` to `127.0.0.1`, and `curl` with a `Host` header always works. Update the "Status" paragraph to say `paas up` exists. Mark roadmap item 10 done. Point to `docs/manual-testing.md` for breaking and repairing a deployment. Leave the rest of the README as it is.
