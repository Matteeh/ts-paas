## Context

Contract: "Reconcile redeploy and ingress" in the `cli` delta.

Today `redeployItems` in `src/commands/reconcile.ts` only looks at `fail` items in the current plan. Replace that selection. Walk `listApps(store)` (already ordered by name) and pick each app that has no running deployment left after the plan, meaning none that is `running` and not failed by the plan. Of those, pick the app when either:
- its latest deployment is failed by this plan for a container reason, which in a dry run is still `running` in the store; or
- its latest deployment is `failed` and `deploymentStatusChanges` for it includes `running`.

Only reconcile moves a deployment from `running` to `failed`, so this excludes health failures, which never reach `running`, and stuck deployments. Do not match on error text: a failed health window also stores an error that starts `container exited with code`. Everything else about redeploy items stays: the details, `ok`, dry-run `planned`, one deploy at a time, and each counting as a change for the ingress push.

While in this file, remove the module-level `WeakMap` that carries container names. Give `ReportItem` a `name` field: the container name for `orphan` and `prune` items, `null` otherwise. Leave it out of the `--json` output, which keeps exactly `{kind, app, deploymentId, containerId, detail, ok}` per item. Task 3 of change 011 imports `runReconcile` and `ReportItem`; keep both exports working.

`tests/reconcile-cli.test.ts` and `tests/status-drift-cli.test.ts` are frozen and must pass unchanged. The change-level `pnpm verify` runs them. The new test file follows `tests/reconcile-cli.test.ts`. Copy its helpers, including the one that advances the clock through a redeploy's health window; do not import from it. Seed a health-failed deployment by deploying an image the `FakeRuntime` scripts to exit with code 3.
