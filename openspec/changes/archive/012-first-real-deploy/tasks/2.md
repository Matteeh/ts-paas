## Context

Contract: "Up command" in the `cli` delta.

Create `registerUp` in `src/commands/up.ts`, and call it in `buildProgram` in `src/program.ts` after `registerReconcile`. Change nothing else in `src/program.ts`. The command accepts `--tls <mode>`, `--http-port <n>` and `--https-port <n>`, parsed exactly as `paas ingress up` does (`parsePort` from `src/commands/format.ts`). It runs inside `runAction` and `withEngine` from `src/commands/context.ts`, which pings the engine before opening the store.

It first ensures `PAAS_NETWORK` (from `src/deployments/types.ts`) with `ensureNetwork`, so the report shows `paas-net: present`. It then builds the doctor report the way `registerDoctor` in `src/commands/doctor.ts` does, with `ping` and `networkExists`, and calls `ingressUp` from `src/ingress/caddy.ts` with `admin: getAdmin(context)`. Last, it prints `formatDoctor(report)`, the ingress line, and `next: paas apps create <name> --image <ref> --port <n> --host <name>.localhost`, with the angle brackets written literally.

The ingress line is built inline in `registerIngressCommand` in `src/commands/ingress.ts` today. Move it into an exported `formatIngressUp(result: UpResult): string` in that file, and use it from both commands. Change nothing else in `src/commands/ingress.ts`; `tests/ingress-cli.test.ts` is frozen and must pass unchanged.

Tests build the program in-process as `tests/ingress-cli.test.ts` does, with a `FakeRuntime`, a `FakeClock`, a `FakeCaddyAdmin` and a temporary `PAAS_HOME`. Copy its helpers; do not import from it. The unreachable-engine case spawns `src/cli.ts` as a child process with a missing `PAAS_SOCKET`, as the child-process test in `tests/deploy-cli.test.ts` does.

## Acceptance
- [ ] On a fresh fake, `paas up` prints exactly the six lines of the "Fresh machine" scenario and exits 0; `paas-net` exists, `paas-caddy` runs, and the admin received one config.
- [ ] A second `paas up` prints the same doctor lines and `ingress is up (unchanged): ...`.
- [ ] `paas up --http-port 8080 --https-port 8443 --tls auto` prints `ingress is up (created): http 8080, https 8443, tls auto, routes 0`, and `paas ingress status` then shows those settings.
- [ ] `paas up --tls on` and `paas up --http-port abc` exit 2 with stderr starting `paas: `, and no `paas-caddy` exists afterwards.
- [ ] With a missing `PAAS_SOCKET`, `paas up` as a child process exits 1 with stderr exactly `paas: cannot reach container engine at <path>: socket not found` and a newline, and creates no `state.db`.
- [ ] `paas --help` lists `up` with a one-line description, and `tests/ingress-cli.test.ts` passes unchanged.
