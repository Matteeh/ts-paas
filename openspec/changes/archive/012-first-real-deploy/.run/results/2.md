## Changed

Added `registerUp` in `src/commands/up.ts`. The `up` command accepts `--tls`,
`--http-port` and `--https-port`, parses ports with `parsePort` exactly as
`paas ingress up` does, and runs inside `runAction` and `withEngine`. It ensures
`PAAS_NETWORK` with `ensureNetwork`, pings the runtime and checks
`networkExists` to build the same `DoctorReport` shape `paas doctor` uses, calls
`ingressUp` with `admin: getAdmin(context)`, then prints `formatDoctor(report)`,
the ingress line and the literal
`next: paas apps create <name> --image <ref> --port <n> --host <name>.localhost`.

Moved the `ingress is up (...)` line out of `registerIngressCommand` into an
exported `formatIngressUp(result: UpResult)` in `src/commands/ingress.ts` and use
it from both commands; nothing else in that file changed. Registered `registerUp`
in `buildProgram` (after `registerReconcile`) and added its import.

Added `tests/up-cli.test.ts`, copying the harness helpers from
`tests/ingress-cli.test.ts` rather than importing them. It covers the fresh
machine six-line output plus the resulting network/Caddy/config, the second-run
`(unchanged)` output, flags stored and shown by `paas ingress status`, both
invalid-value cases creating no Caddy, the missing-`PAAS_SOCKET` child process
(exit 1, exact stderr, no `state.db`), the help description, and the stored
settings.

## Deviated

An invalid `--tls` mode is validated by `ingressUp`/`setIngressSettings` inside
`withEngine`, after `ensureNetwork`, because the task says to parse flags exactly
as `paas ingress up` does and `up` therefore does not validate TLS at the flag
level. The acceptance only requires no `paas-caddy` to exist, which holds since
validation happens before any container call. `--http-port abc` is still caught
by `parsePort` before `withEngine`.
