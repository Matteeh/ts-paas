## Changed

Reworked the `--redeploy` selection in `src/commands/reconcile.ts`. It no longer
reads `fail` items in the current plan. It now walks `listApps` (name order) and
picks an app when it has no running deployment left after the plan and either its
latest deployment is failed by this plan for a container reason, or its latest
deployment is `failed` and its status history includes `running`. Health failures
(never `running`) and stuck deployments are therefore excluded. Redeploy items keep
their output, one-at-a-time behavior, dry-run `planned` detail, and count as changes
for the ingress push. The redeploy loop no longer dedupes with a `Set` from the plan;
each app is visited once by construction.

Removed the module-level `WeakMap` that carried container names. `ReportItem` now has
a `name: string | null` field; orphan/prune items set it, every other item sets
`null`. Human formatting reads `item.name`; `--json` output goes through a new
`jsonReport` projection so each item keeps exactly the six documented keys. The
exported `runReconcile` and `ReportItem` interfaces still work for status drift.

Added `tests/reconcile-redeploy-cli.test.ts`, copying the helpers from
`tests/reconcile-cli.test.ts` rather than importing them, including the
advance-through-the-health-window helpers. It covers an earlier-run failure being
redeployed, dry-run planning, a health-failed app, a stopped app, a stuck
deployment, two earlier failures redeployed in name order, orphan/prune container
names plus the `name` field on `runReconcile` items, the six JSON keys, and the
absence of `WeakMap` in the source.

Verified: `node --import tsx --test tests/reconcile-redeploy-cli.test.ts` passes (9
tests), and the proposal's `pnpm verify` passes (tsc plus 382 tests, including the
frozen `tests/reconcile-cli.test.ts` and `tests/status-drift-cli.test.ts`).
